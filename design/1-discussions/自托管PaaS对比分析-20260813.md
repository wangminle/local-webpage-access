# 自托管 PaaS 系列 × LWA 功能对比分析（2026-08-13）

> 分析范围：Coolify / Dokploy / CapRover / Dokku / Piku / Rainbond / 1Panel / CasaOS / Tipi / Umbrel 为主样本；dploy、Forge 仅作备注（0★，不对等）。Easypanel / Komodo / Dockge / Cosmos / Kamal 见姊妹文档，未纳入本表。
>
> 数据源：官方 README **以及** 已核对的文档子页（Dokku archive、Dokploy rollbacks/preview、CapRover captain-definition、Rainbond v5.15 安装、Caddy Local HTTPS、SQLite Backup API）。**未逐项读竞品源码与插件实现。** 星标与仓库状态为 2026-08-13 GitHub API 快照。
>

## 三、维度一：建议添加的 Feature（四维评分）

评分取 高 / 中 / 低。综合档：P0 优先评估实现；P1 值得规划但不是「加个命令」；P2 可做、跨平台或成本风险更高。

| 项 | 用户价值 | 实现成本 | 运维风险 | 跨平台难度 | 档 |
|---|---|---|---|---|---|
| Git 导入 / 从 Git 更新 | 高 | 中（clone 后走现有识别流水线） | 中（webhook 攻击面，宜后置） | 低 | **P0** |
| 内网 HTTPS（内部 CA） | 高 | 中 | 中（根证书分发、SAN/换 IP 重签） | 高（每台客户端、部分浏览器独立信任库） | **P0** |
| 部署/实例事件通知 | 高 | 低（已有 events 表） | 低 | 低 | **P0** |
| SQLite 可靠备份 + 恢复 | 高 | 中（Online Backup / VACUUM INTO + 多库一致性） | 中（恢复后完整性） | 低 | **P0** |
| 版本回滚 | 高 | **高**（无版本表、无镜像映射、无 schema 策略） | 高 | 中 | **P1** |
| 资源水位告警 + 小图表 | 中 | 低 | 低 | 低 | **P1** |
| 原生 Prometheus `/metrics`（对照列多为 Sentinel / monitoring extension，不是原生端点） | 中 | 低 | 低 | 低 | **P1** |
| mDNS `myapp.local` | 中 | 中 | 中（冲突、多网卡、客户端支持） | **高**（Linux Avahi / macOS Bonjour / WSL2） | **P2** |
| 精选模板 10~20 个 | 中 | 中 | 低 | 低 | **P2** |
| 应用级定时任务 | 中 | 中 | 中 | 低 | **P2** |

### P0 —— 优先评估

1. **Git 导入源与从 Git 更新**（`lwa import --from-git <url>`，以及已有实例的 git 更新）
   借鉴：Dokku / Piku / Coolify / Dokploy 的主入口。LWA 不必放弃 zip：clone（或 fetch）到暂存后走同一识别流水线，即可覆盖「作者本人迭代部署」。Webhook 触发可第二步再做，先做 CLI/管理页的 Git 源，避免一上来扩大攻击面。

2. **内网 HTTPS（内部 CA + 浏览器信任引导）**
   借鉴：Piku（Let's Encrypt + 失败则 openssl 自签，**不是**可分发的内部 CA）、CapRover/Dokku 的 LE 插件。LWA 默认内网，用 Caddy internal CA 给 `https://<lan-ip>:…` 和路径别名签发即可。
   成本不可写轻：每台客户端必须单独安装根 CA；部分浏览器可能忽略系统信任库；DHCP 换 IP 要改证书 SAN 并重签。见 [Caddy Local HTTPS](https://caddyserver.com/docs/running)、[Automatic HTTPS](https://caddyserver.com/docs/automatic-https)。收益仍真实：非 https 下剪贴板、摄像头、Service Worker 等 API 会被浏览器关掉。

3. **部署/实例事件通知（webhook）**
   借鉴：Dokploy（Slack/Discord/Telegram/Email）、Coolify。LWA 已有 events 表和构建队列状态机，缺 sink。建议 `ntfy / 企业微信 / 钉钉 / 飞书 / Telegram / 通用 webhook`，覆盖构建成败、实例掉线、LAN IP 漂移、磁盘水位。

4. **SQLite 可靠备份 + 一键恢复（禁止普通硬链接当快照）**
   借鉴：1Panel 一键备份、Coolify/Dokploy 的 S3 备份。LWA 的数据面是文件，但 **普通硬链接与源库共享 inode，后续写入会改掉所谓备份，不能当历史快照。**
   应采用下列之一，并在恢复前后做完整性检查：
   - Python `sqlite3.Connection.backup()` / [SQLite Online Backup API](https://sqlite.org/backup.html)；
   - [`VACUUM INTO`](https://sqlite.org/lang_vacuum.html#vacuuminto)；
   - 或明确限定在 Btrfs / ZFS / APFS 等**写时复制**文件系统快照上。
   还要考虑 Registry、各实例 `data/` 下的 SQLite、以及 `local-web.yml` / manifest 之间的一致性，不能只拷一个文件。命令面可以是 `lwa backup` / `lwa restore`，实现不是「WAL checkpoint + ln」。

### P1 —— 值得规划，不是「加个 CLI」

5. **版本回滚**：Dokploy（Swarm 自动回滚 + registry 任意版本）、CapRover、Rainbond、Coolify 都说明这是品类标配。
   LWA **没有**现成版本链：`--update` 成功后会删掉 `current.old`，只留一份 `original.zip.bak`；没有版本表、保留策略、镜像/构建产物与源码的映射，也没有配置 / 端口 / 数据 schema 的兼容与恢复策略。做成 `lwa rollback <id> <version>` 至少是中等规模功能。

6. **资源水位告警 + 指标历史小图表**：复用已有 stats 与 P0 通知通道。Dokploy/Coolify 是标配心智。

7. **原生 Prometheus `/metrics`**：实现成本低。Coolify 公开资料是实验性 [Sentinel 指标](https://coolify.io/docs/knowledge-base/server/sentinel)，Dokploy 是 [monitoring extension](https://docs.dokploy.com/docs/templates/dokploy-prom-monitoring-extension)，都不能当成「竞品已有原生 `/metrics`」。Forge 有先例但 0★，只当接口形态参考。

### P2 —— 可规划，跨平台或会滑向商店

8. **mDNS 局域网主机名（`myapp.local`）**：Piku 的 [avahi-aliases](https://github.com/piku/avahi-aliases) 是 LAN 先例，但该仓约 10★、2020 年后停更。`.local` 是 mDNS 特殊域，要处理名称冲突、客户端支持、网络隔离、多网卡；Linux 用 Avahi，macOS 用 Bonjour，WSL2 更脏。**不是「装个 Avahi 即可」。** 体验有价值，放到 P2，等内网 HTTPS 和 Git 稳定后再做。

9. **精选模板**（10~20 个家庭常用配方）：Coolify 280+、1Panel 231、CasaOS 都以商店为核心。LWA 只做少量精选、走自家 import 管线，避免变成商店。

10. **应用级定时任务**：Dokku cron 插件。容器定时重启、静态定时重建。

## 四、维度二：与定位不同、不建议照搬

这些不是对方做错了，而是目标环境（公网 VPS / 企业 / 多机）与 LWA（局域网单台小主机、导入即用）不同：

| 对方 Feature | 为什么定位不同 | 建议 |
|---|---|---|
| 公网域名 + Let's Encrypt（Coolify/Dokploy/CapRover/Dokku/Rainbond） | 它们默认对公网服务；LWA 默认内网 | 不跟公网证书；走 P0 内网 CA。穿透留给用户自接 frp/Tailscale |
| 多服务器 / Swarm / K8s（Coolify、Dokploy、CapRover、Rainbond） | LWA 的端口池/registry/锁按单机建模。Rainbond 是 K8s，v5.15 主机安装最低 2C/4G/50GB+，推荐或旧文档常见 8G——**不能**据此说 4G/8G 小主机绝对跑不动，但明显重于 LWA。Coolify 官方最低 2C/2G，4G/8G 能跑 | 明确「单机是特性」；不碰多机 |
| 托管数据库即服务 | LWA 场景是项目自带 SQLite | 只做可靠 SQLite 备份（P0-4），不建 DBaaS |
| 应用商店作为核心（CasaOS/Umbrel/Tipi/1Panel） | 商店卖别人打包好的应用；LWA 卖把你的项目跑起来 | 只做少量精选模板（P2-9） |
| Preview Deployments（Coolify、**Dokploy 完整 GitHub PR Preview**、Rainbond 多环境） | 依赖公网 Git PR + 域名 | 不做 |
| 白标定制（dploy） | 卖 PaaS 给客户 | 个人工具阶段不做 |
| Web 终端/文件管理器 | 滑向通用服务器面板 | 最多做容器 exec 日志流 |
| WAF / 站点可用性监控（1Panel Pro） | 运行时 WAF 对内网过重 | 不跟 |
| 多用户 / 团队 / SSO | 家庭小主机单管理员 | 不做角色系统 |
| 离线交付 / 信创（Rainbond） | 企业 B2B | 不跟 |
| AI 网关 / 模型管理（1Panel **企业版** Metal-to-Agent） | 托管模型 ≠ 让 AI 操作部署 | 可观察；当前不跟 |

## 五、维度三：本样本中 LWA 相对完整或少见的能力

下列判断的证据边界是：**本次抽样项目 + 已核对公开文档**。可能被源码/插件打脸。

1. **zip/文件夹 + inbox 自动导入**：CapRover、Dokku `git:from-archive`、Rainbond 源码包都能吃压缩包。本样本中未见「inbox 守护进程自动导入并启动可确定的轻量实例 + 免手写配置识别」的对等产品。Coolify/Dokploy 主路径不吃 zip。
2. **五层识别流水线主体**：Piku/Dokku/nixpacks 是「看文件猜语言/构建」。LWA 另有 Gate-A 预检、Gate-B 多候选契约、Gate-C 实证状态机。**完成度**：主体已实现；Gate-A 原战术范围已落地，A.R01 尚未收口；Gate-C 模拟回归通过，真实 Docker 门控见 [[TST-005]]（进行中）。[Scanner 设计文档](../2-achievement/Scanner架构设计分析-多候选与实证校验-20260811.md) 明确禁止在该门控前宣称全部退出标准已满足。识别**深度**在已核对资料里更完整，不宜写「全组第一」。
3. **LAN 地址治理**：lanUrl 读时合成、DHCP 漂移节流、`access review`（空 200 / 404 / 错误 MIME / JS bundle API 错位）。其他家多假设 DNS 存在。Piku 只有停更的 avahi-aliases 外围件。
4. **端口池隔离**：registry + 宿主机监听双重查重 + 端口稳定复用。对照列多为子域名模型。
5. **路径别名 + SPA 兼容性门禁**：不兼容则拒绝并给重建建议。已核对资料中未见对等。
6. **构建队列跨进程闸门**：LWA 同时覆盖默认并发 1、跨进程槽位、排队超时，以及排队中/运行中构建取消，面向 4G/8G。Coolify 有并发限额；Dokploy 可取消排队中的部署。这里比较的是这些语义的组合完整度，不是「只有 LWA 有队列」。
7. **源码/归档导入安全**：LWA 在 zip 成员 + **平台生成的** Dockerfile/Compose 写前拦截 `ADD <url>`、`curl|sh`；Dokku 在归档提取前拒绝路径穿越/symlink。该能力不等于对任意自带 Dockerfile、构建脚本或源码提供完整审计/沙箱。Rainbond 离线安装包完整性属于平台制品校验，1Panel WAF 属于运行时流量防护，均不能当作同层能力比较。**不是**「12 家都只部署你给的东西」。
8. **网关原子切换 + 工作区原子迁移**：本样本公开资料中未见对等的工作区 migrate/verify/rollback 工具。
9. **`lwa doctor` + 平台矩阵 + Full Profile 能力契约**：未初始化也能出 JSON；失败标 SKIP 不假绿。已核对资料中未见同等「信任边界」设计。
10. **19 个 SKILL.md**：与 CLI 绑定、覆盖完整部署工作流。1Panel Skills Hub 是**企业版**技能资产管理，方向相近但不是社区版对等物。
11. **`lwa update` 热重载编排**：等导入完成 → 同步 skills → 补配置 → 重启 → 刷新地址 → 能力验收。比「面板 auto-update」更面向裸机可信升级。
12. **应用级浏览量统计**：对照列多为服务器级流量。

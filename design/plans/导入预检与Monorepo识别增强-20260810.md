## 1. 背景与动机

### 1.1 两个独立问题

IMP-055 在**设置别名时**才做兼容性门禁。部署 `patent-disclosure-workflow-v1` 时，实际暴露的是**两个可拆开的问题**：

| 问题 | 现象 | 近端解锁方式 | 归属 |
| --- | --- | --- | --- |
| **A. Scanner 不识 Monorepo** | 根 `package.json` 只有工作区/devDeps → `unknown`/`pending`，需手配 compose | 增强 scanner 读子包 | **IMP-057（Gate-1 必达）** |
| **B. 项目无 base path 意识** | SSR HTML 里 `fetch('/api/...')`、路由硬编码绝对路径 → 别名下 API 空壳 | 导入时静态提示 + 别名时仍由 IMP-055 兜底 | **IMP-056（Gate-2）** |

初稿把 A+B 绑成同一交付。本版改为：**先解锁导入与启动（A），再做别名提前告知（B）**。Problem B 在 Gate-1 发布后仍可通过 IMP-055 在设别名时强制拦截；Gate-2 只是把告知提前到 import。

### 1.2 触发案例：patent-disclosure-workflow-v1

**问题 A — Scanner 不识别 Monorepo**

npm workspaces monorepo：根 `package.json` 仅含 `devDependencies`（typescript、vitest 等），不含 `NODE_FRONTEND`/`NODE_BACKEND` 标记依赖。现有 `summarize()` 只读根 `package.json`，`_is_real_node()` 失败 → pending。

**问题 B — 无 base path 意识**

| 层面 | 现状 | 后果 |
| --- | --- | --- |
| 服务端路由 | 硬编码 `path === '/api/status'` | 不接受前缀 |
| 客户端 JS | `const API = ''` + `fetch('/api/status')` | 打到入口根而非 `/<alias>/api/...` |
| 代理头 | 不读 `X-Forwarded-Prefix` | 不知被代理 |
| 环境变量 | 无 `BASE_PATH` | 无法注入前缀 |

别名下 HTML 能加载，API 返回空响应 → 页面空壳。端口直连仍可用。

### 1.3 Electron 混合 monorepo

| 子包 | 内容 | Web 可部署 |
| --- | --- | :---: |
| `packages/core` | 共享业务逻辑（库） | 构建依赖（不单独部署） |
| `packages/webpage` | Web HTTP server + 内联前端 | ✅ 部署目标 |
| `packages/desktop` | Electron（`electron: 40.10.3`） | ❌ 跳过 |
| `packages/runtime` | 仅 `logs/` 等 | ❌ 跳过 |

Scanner / 预检必须跳过桌面包，否则 `file://`、`ipcRenderer` 等会制造噪声。

### 1.4 现有代码锚点（实现时必读）

| 能力 | 位置 | 说明 |
| --- | --- | --- |
| 真 Node 判定 | `scanner.py`：`NODE_FRONTEND` / `NODE_BACKEND`、`_is_real_node`、`_detect_node` | 只看当前 `FileSummary` 的 deps/scripts |
| 根摘要 | `scanner.py`：`summarize(project_dir)` | **仅解析根** `package.json` |
| HTML 绝对资源门禁 | `path_alias.reject_alias_if_absolute_spa_assets` → `access._extract_absolute_resources` | IMP-055 资源侧 |
| API 路径错位 | `access._extract_api_paths` / `_check_api_paths` | IMP-055 API 侧（运行时对照） |
| 导入完成路径 | `importer.py`（`import_zip` / `import_from_dir`）+ `cli/importing.py` | **不是** `hosting.py` |
| doctor CLI | `cli/system.py` → `doctor.py` | 不是 `cli/doctor.py` |
| workspaces COPY | `dockerfile_templates._node_dependency_copy_block` | 已支持 npm `"workspaces"`；pnpm/yarn 早退 |

## 2. 设计目标与门禁

### 2.1 目标（按优先级）

| 优先级 | 目标 | Gate |
| --- | --- | --- |
| P0 | Monorepo 可被自动识别为可部署形态，并生成**可启动的** entry（install/build/start + cwd/workspace 语义） | Gate-1 |
| P0 | 混合仓中跳过 Electron / 纯库 / 运行时目录，避免误选主包 | Gate-1 |
| P1 | 导入登记后给出别名兼容性**建议**（默认 CHK-P03/P04），不阻断导入/启动 | Gate-2 |
| P1 | 预检与 IMP-055 互补：预检提前告知，**IMP-055 仍是唯一 enforce** | Gate-2 |
| P2 | doctor / list ⚠️ / 规则扩展（P01/P05…） | Gate-2 后或同 Gate 可选 |

### 2.2 明确非目标（本计划不做）

- 不阻断导入、不阻断启动、**不用预检结果硬拒 `alias set`**
- 不在本计划内完整支持 pnpm / Yarn / Nx / Lerna / Rush workspace 发现（见 §12）
- 不自动给用户项目打补丁改 `BASE_PATH`（只给修复建议）
- 不实现「一仓多实例」自动展开（多可部署包 → pending + 说明）
- 不把预检做成通用前端 lint 产品（Router/端口/VITE_BASE 等后置）

### 2.3 两道发布门禁

```
Gate-1（IMP-057）必须可独立发布
  └─ patent-disclosure 类 monorepo：识别成功 + 可 start（端口直连）

Gate-2（IMP-056）在 Gate-1 之后
  └─ 导入后打印 CHK-P03/P04 建议；findings 写入 local-web.json
  └─ alias set 行为与今日一致：只信 IMP-055
```

关闭 patent-disclosure「无法自动导入」工单的条件是 **Gate-1**，不是 Gate-2。

## 3. 导入门禁分层模型（定稿）

```
项目源码进入 LWA（lwa import）
       │
       ▼
┌─────────────────────────────┐
│  第一层：Scanner 识别        │
│  ★ Gate-1：Monorepo 包分类   │
│    + 选主包 + entry/cwd     │
└──────────┬──────────────────┘
           │
     识别成功？
     ├─ 是 → 登记实例（status=stopped/pending），进入第二层（若已启用 Gate-2）
     └─ 否 → pending + notes（含多包/无包原因）
           │
           ▼
┌─────────────────────────────┐
│  第二层：兼容性预检（Gate-2） │
│  静态源码扫描，写入 findings  │
│  性质：真正 advisory         │
└──────────┬──────────────────┘
           │
           ▼  （无论有无 finding：均不阻断）
     导入完成。构建/启动由用户执行 lwa start。
     有 finding → 打印 ⚠️ + 指向 lwa doctor（若已接）
           │
           ▼
┌─────────────────────────────┐
│  第三层：IMP-055 别名门禁     │
│  用户 lwa alias set 时       │
│  ★ 始终执行运行时/入口探测   │
│  ★ 不读取预检 critical 做快拒│
└─────────────────────────────┘
```

### 3.1 分层原则表

| 层级 | 时机 | 性质 | 阻断导入？ | 阻断启动？ | 阻断别名？ |
| --- | --- | --- | :---: | :---: | :---: |
| 第一层 Scanner | 导入时 | 自动识别 | ❌（失败则 pending） | — | — |
| 第二层 预检 | 导入后（同步） | **advisory** | ❌ | ❌ | ❌ |
| 第三层 IMP-055 | 设别名时 | **enforce** | — | — | ✅ |

**关键原则**：

1. 预检的目的是**知情**，不是阻断任何操作。
2. `alias set` **始终**跑 IMP-055（含 HTML 绝对资源 + API 路径运行时对照等既有逻辑）。预检结果最多用于**文案增强**（例如在拒绝信息中附加 doctor 里已记录的静态线索），不得跳过探测。
3. `lwa import` **只**解压 / 识别 / 登记；**不**自动构建、**不**自动启动（与现有 `cli/importing.py` 一致）。

### 3.2 认识论边界（静态 ≠ 运行时）

| 证据类型 | 可信度 | 允许的产品动作 |
| --- | --- | --- |
| 静态源码 grep（CHK-P03/P04） | 启发式 | 仅 warning/critical **展示**；不 enforce |
| 入口 HTML 绝对资源（IMP-055 / `_extract_absolute_resources`） | 与别名失败同构 | enforce（已有） |
| 运行时 API 对照（`_check_api_paths`） | 与别名失败同构 | enforce（已有） |

因此：**不得**把「静态 critical」提升为「可跳过 IMP-055 的真源」。CHK-P04「源码中是否出现 `BASE_PATH` 字符串」尤其不能等同于「已正确支持前缀」。

## 4. Monorepo 包分类（IMP-057 / Gate-1）

### 4.1 检测触发条件（本计划范围）

**纳入本计划**：

1. 根 `package.json` 含 npm `"workspaces"` 字段（数组或 `{ packages: [...] }`）；或
2. 存在 `packages/*/package.json` 且根含 `package.json`（作为弱信号，与 workspaces 解析结果取并集，去重）。

**显式延期（known-limitation）**：

- `pnpm-workspace.yaml`
- Yarn / Lerna / Nx / Rush 专用清单
- Python / Go / Cargo workspace

延期项须写入 `docs/known-limitations.md`（任务 D.02），避免对外暗示「任意 Monorepo」。

### 4.2 PackageType 枚举（统一 6 值）

| 枚举值 | 含义 | `isDeployable` | 扫描 / 选主 |
| --- | --- | :---: | --- |
| `electron_desktop` | 含 `electron` 依赖 | false | 硬跳过 |
| `library` | 有 `main`/`exports`，无后端框架，无部署型 start/server | false | 不选主；预检默认不扫 |
| `web_server` | Node HTTP 服务 / SSR | true | 选主候选 |
| `frontend_build` | 纯前端构建后静态托管 | true | 选主候选（无 web_server 时） |
| `runtime_data` | 无有效 `package.json`，或仅 logs/data | false | 跳过 |
| `unknown` | 无法归类 | false | 见 §4.6 扫描策略 |

> 「5 种业务类型 + unknown」共 6 个枚举值。验收文案写「6 值枚举」，勿再写含糊的「5 种」。

### 4.3 分类规则（优先级从高到低）

对每个子包目录读取 `package.json`（若无 → `runtime_data`）：

```text
1. deps∪devDeps 含 "electron"（大小写不敏感）
     → electron_desktop
     （description 关键词仅作 info 日志，不作为分类依据，降低误伤）

2. deps∪devDeps ∩ NODE_FRONTEND 非空
   且 无 NODE_BACKEND
   且 有 scripts.build
     → frontend_build
   （注意：有 scripts.dev 不足以升 web_server）

3. deps∪devDeps ∩ NODE_BACKEND 非空
   或 scripts 含 "server"
   或（scripts 含 "start" 且 非步骤 2 的纯前端）
     → web_server

4. 有 main 或 exports
     → library

5. 否则
     → unknown
```

**与初稿的关键差异**：

- **禁止** `has_server_script = any(dev|start|server)` 这种宽规则。
- `dev` **单独出现绝不**构成 `web_server`。
- 纯前端（Vite 等）在步骤 2 截获，避免被 `dev`/`start` 误升到容器路径。
- HTTP 框架集合与 `scanner.NODE_BACKEND` **共用同一常量**（计划文案中的 `hono` 应对齐实现：当前集合含 `@hono/node-server`；若要认裸 `hono`，在 Gate-1 同步扩常量，见 WBS A.02）。

### 4.4 选主包决策表

`DetectionResult` / `InstanceManifest.entry` 是**单值**的，必须定义多候选行为：

| 可部署候选 | 行为 |
| --- | --- |
| 0 个 `web_server` 且 0 个 `frontend_build` | `pending`；notes：`monorepo 中未发现 Web 可部署子包` |
| 恰好 1 个 `web_server` | 选该包为主包 |
| ≥1 个 `web_server` 与任意 `frontend_build` | **只在 `web_server` 中选**；忽略 frontend_build 作为主包 |
| 恰好 1 个 `frontend_build`（无 web_server） | 选该包 → 走现有 frontend-static 路径 |
| ≥2 个 `web_server` | `pending`；notes 列出候选路径，提示后续可加 `--package`（本计划不实现 CLI 旗标，只留 notes 契约） |
| ≥2 个 `frontend_build`（无 web_server） | 同上 pending |

产品语义：**一仓一实例**；多 app 仓本阶段不自动拆实例。

### 4.5 Scanner 增强与 entry/cwd（负载决策）

仅「用子包 deps 喂 `_is_real_node()`」**不够**。必须同时重塑用于 `_detect_node` 的摘要，否则根无 `scripts.start` 时会生成不可运行的 `node server.js`。

**定案（Gate-1 必须交付）**：

1. 解析 workspaces → `classify_packages` → 按 §4.4 选主包 `primary`。
2. 构造面向主包的摘要（任选实现，但行为等价）：
   - **推荐**：`summarize_package(root, primary.path)`：deps/scripts 来自子包 `package.json`；锁文件/包管理器仍看**仓库根**（`pnpm-lock.yaml` / `package-lock.json` 等）。
   - 或：合成 `FileSummary`，把子包 deps/scripts 填入后再调 `_is_real_node` / `_detect_node`。
3. **entry 约定**（npm workspaces，本计划范围）：
   - `install`：仍在**仓库根**执行（`npm ci` / `npm install`，由现有 `_node_install_command` 决定）。
   - `build`：若主包有 `build` → `npm run build -w <pkg-name>`（`<pkg-name>` 取 package.json 的 `name`；若无 name 则用相对路径过滤器，实现时单测钉死一种）。
   - `start`（仅 `web_server`）：`npm run start -w <pkg-name>`；若主包无 `start` 但有 `server` → `npm run server -w <pkg-name>`。
   - Dockerfile：`WORKDIR` 仍为 `/app`（整仓拷贝）；CMD 使用上述 start 字符串。§4.4 已有的 workspaces `COPY` 子包 `package.json` 逻辑保持。
4. 端口推断：优先读主包源码/脚本中的端口线索；回退现有 `_infer_node_port`。
5. `DetectionResult.notes` 记录：`primary=packages/webpage (@scope/webpage)`、各包分类摘要。

**Frontend-static 主包**：`build` 用 `-w`；产物目录需可被现有静态发布逻辑找到——若子包 `dist/` 不在根，Gate-1 验收必须覆盖「构建产物路径」或在 notes 中明确限制（WBS A.07）。

### 4.6 预检扫描范围（供 Gate-2；分类器在 Gate-1 已具备）

```text
若存在高置信 deployable（web_server ∪ frontend_build 且已选主）：
  默认只扫 primary.path（MVP 预检）
  electron_desktop / runtime_data：永不扫
  library / unknown：MVP 不扫（接受「共享库内绝对路径、构建期打进 webpage」的漏报残余，见风险表）

若无 deployable（非 monorepo 或分类全失败）：
  扫整个 source_dir，但应用 §4.7 排除目录
```

与「无法确定则全盘扫」的初稿缓解不同：**已有主包时不因 unknown 旁路而全盘扫**，避免 Electron 噪声；漏报由 IMP-055 兜底。

### 4.7 排除目录（硬编码）

```python
EXCLUDE_DIRS = frozenset({
    "node_modules", ".git", ".venv", "venv", "__pycache__",
    "dist", "build", ".next", ".nuxt", "out",  # 构建产物：导入期通常不存在
    ".pytest_cache", ".mypy_cache", ".ruff_cache",
    "tests", "docs", "examples",
})
```

**定案**：导入期预检**不依赖** `dist/`。后置的产物级检查（若做）必须在 `lwa start`/`scan` 且产物已存在时**显式允许**扫描指定路径，而不是从本集合删掉 `dist` 导致全盘变慢。

## 5. 兼容性预检规则（IMP-056 / Gate-2）

### 5.1 规则分层

| 编号 | 检查项 | 默认严重级别 | Gate-2 MVP | 说明 |
| --- | --- | --- | :---: | --- |
| **CHK-P03** | SSR/服务端模板中绝对 API 路径、`const API = ''` | critical（展示用） | ✅ | patent-disclosure 主痛点 |
| **CHK-P04** | 源码未见 base path / 代理前缀线索 | warning | ✅ | 启发式；文案须标明「未证明不兼容」 |
| CHK-P01 | 入口/静态 HTML 绝对资源路径 | critical（展示用） | ⭕ 可选 | 优先**调用** `_extract_absolute_resources`，不重写；无 HTML 则跳过 |
| CHK-P02 | 源码/产物中绝对 API 路径 | critical（展示用） | ❌ 后置 | 复用 `_extract_api_paths`；**禁止**挂 `reject_alias_if_absolute_spa_assets` |
| CHK-P05 | Vue Router `createWebHistory('/')` | warning | ❌ 后置 | 通用前端，非本触发案例 |
| CHK-P06 | 硬编码 localhost:port | warning | ❌ 后置 | 噪声高 |
| CHK-P07 | 构建配置无 base | info | ❌ 后置 | |
| CHK-P08 | Electron 包混入提示 | info | ❌ 不做 | 分类跳过已覆盖；勿重复产品面 |

### 5.2 MVP 规则详情

#### CHK-P03：SSR / 服务端模板绝对 API 路径

**扫描目标**：主包（或非 monorepo 的 source_dir）下 `.ts`/`.js`/`.mjs`/`.cjs`/`.py`（应用 §4.7 排除）。

**匹配（示例）**：

```regex
(fetch|axios\.\w+)\s*\(\s*['"`]/api/
```

以及明显的空 API base：`const API = ''` / `const apiBase = ""`（可再收紧，避免误伤测试夹具——夹具目录已在 EXCLUDE）。

**patent-disclosure 期望**：命中 `packages/webpage/src/server.ts` 中 `const API = ''` 与多处 `fetch('/api/...')`。

**修复建议文案**：支持 `BASE_PATH`（或等价），注入客户端常量，并在路由匹配前剥前缀。

#### CHK-P04：未见 base path / 代理前缀线索

**检查方式**：在主包源码中搜索（大小写不敏感）：

- `BASE_PATH` / `BASE_URL` / `X-Forwarded-Prefix` / `x-forwarded-prefix` / `SCRIPT_NAME`

命中 0 个 → 一条 **warning**（不是 critical）。

**文案必须包含**：`此为启发式：未检出常见关键字 ≠ 一定不兼容；设别名时仍以 IMP-055 运行时探测为准。`

### 5.3 可选 / 后置规则（摘要）

- **CHK-P01**：对 `index.html` / `public/index.html`（若存在）跑 `_extract_absolute_resources`；不扫 `dist`（导入期）。
- **CHK-P02**：对源码 JS/TS 跑 `_extract_api_paths` 同类静态提取；与 IMP-055 运行时探测互补，但**不能**替代之。
- **CHK-P05–P07**：仅当另立目标「通用前端别名静态体检」时启用。
- **CHK-P08**：删除；Electron 由分类器跳过。

### 5.4 执行时机与 findings 生命周期

| 事件 | 行为 |
| --- | --- |
| `lwa import` 成功登记后 | **同步**跑预检（预算 §10.2）；写入 `compatibilityFindings`；打印摘要 |
| `lwa scan` | 重跑预检并覆盖 findings |
| 源码更新（`--update` / 再导入） | 重跑预检并覆盖 findings |
| `lwa alias set` | **不**因 findings 短路；始终 IMP-055；可选在拒绝文案中引用最近 findings |

陈旧 findings 的缓解：任何改写 `current/` 的官方路径都应重跑；文档写明「手工改 current 后请 `lwa scan`」。

## 6. 交互流程（示例）

### 6.1 Gate-1 导入（尚无预检或预检未启用）

```text
$ lwa import patent-disclosure-workflow-v1.zip

  ├─ 🔍 Scanner 识别...
  │   检测到 npm workspaces monorepo
  │   ┊  分类：core=library, webpage=web_server,
  │   ┊        desktop=electron_desktop, runtime=runtime_data
  │   ┊  主包：@patent-disclosure/webpage (packages/webpage)
  │   识别结果：node / docker-compose / port …
  ├─ 实例已登记：patent-disclosure-workflow-v1 (stopped)
  └─ 下一步：lwa start patent-disclosure-workflow-v1
```

### 6.2 Gate-2 导入（含预检）

```text
$ lwa import patent-disclosure-workflow-v1.zip
  ├─ …（同上 Scanner）…
  ├─ 🔍 兼容性预检（建议，不阻断）...
  │   🔴 CHK-P03  SSR 模板绝对 API 路径（展示级 critical）
  │      📄 packages/webpage/src/server.ts:1042  const API = ''
  │   🟡 CHK-P04  未检出常见 base path / 代理前缀关键字
  │      💡 启发式：设别名时仍以 IMP-055 为准
  ├─ 实例已登记：… (stopped)
  └─ ⚠️  发现兼容性提示；端口直连可用，路径别名可能失败
      详见：lwa doctor <id>
      设别名时仍会执行 IMP-055 运行时探测
```

### 6.3 doctor（Gate-2）

分级展示 checkId / severity / file / line / code / impact / fix；结论区分：

- 「预检提示：别名**可能**不可用」
- 「端口直连：…」
- 「强制结论仅在 `lwa alias set` 时由 IMP-055 给出」

### 6.4 list（可选，Gate-2+）

有非空 findings 时标 ⚠️，附 `lwa doctor` 指引。无 findings 不标。

### 6.5 alias set（定稿行为）

```text
$ lwa alias set <id> <alias>
  → 始终执行 IMP-055（HTML 资源 + API 对照等）
  → 若失败：既有错误文案；若 manifest 有 findings，可追加「导入预检曾提示：…」
  → 若成功：即使曾有静态 warning，以运行时为准放行
```

**禁止**：`if findings has critical: return reject` 且跳过 IMP-055。

## 7. 数据结构

### 7.1 CompatibilityFinding（Gate-2）

```python
class CompatibilityFinding(BaseModel):
    checkId: str          # "CHK-P03"
    severity: str         # "critical" | "warning" | "info"  （仅展示分级）
    title: str
    file: str | None      # 相对 current/
    line: int | None
    code: str | None
    impact: str
    fix: str
```

### 7.2 存储（MVP）

```python
class InstanceManifest(BaseModel):
    ...
    compatibilityFindings: list[CompatibilityFinding] = Field(default_factory=list)
```

- **只写** `apps/<id>/local-web.json`。
- **暂缓** `instances.compatibility_findings_json` DB 列与 `dao.upsert_from_manifest` 映射（避免只加 ALTER 不写 upsert 的半成品）。若后续 list/doctor 必须读 DB，另开任务同时改 dao + schema version。

### 7.3 PackageClassification（Gate-1 运行期；落盘可选）

```python
class PackageClassification(BaseModel):
    name: str
    path: str             # "packages/webpage"
    packageType: str      # 六枚举之一
    isDeployable: bool
```

- Gate-1：**不必**持久化到 manifest；`DetectionResult` 可临时携带 `classifications` + `primary_package` 供 notes/entry 使用。
- 若调试需要，允许写入 manifest 可选字段 `packageClassifications`（非 MVP 验收项）。

### 7.4 DetectionResult 扩展（Gate-1 必需）

在现有 `DetectionResult` 上增加（名称可微调，行为固定）：

- `classifications: list[PackageClassification] = []`
- `primary_package: str | None`（相对路径）

`importer.build_manifest_from_detection` 须映射 notes / entry；分类列表按 §7.3 决定是否落盘。

## 12. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 静态误报 | 用户忽视提示 | 展示分级 + 文案声明启发式；不 enforce |
| 静态漏报 | 设别名才发现 | IMP-055 兜底（接受 Gate-1-only 时的体验） |
| 分类假阴性（webpage 被标 library） | 选错主包 / pending | 单测 + 保守：双候选 pending 优于静默错选 |
| 分类假阳性（工具包 start → web_server） | 选错 | 要求 NODE_BACKEND 或非前端的 start/server；案例单测 |
| 共享库内绝对路径未扫 | 漏报 | 接受为残余；后置可扩扫 library |
| pnpm monorepo 仍 pending | 范围外用户失望 | known-limitations 明示 |
| findings 在手工改 current 后过期 | 误导 | 文档要求 `lwa scan`；update/reimport 重跑 |
| 大型仓预检变慢 | 体验差 | EXCLUDE_DIRS + 只扫 primary |

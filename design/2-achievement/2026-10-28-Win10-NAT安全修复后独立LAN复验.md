## 原始异常与解释

1. 旧测试 HTTP 端口 49480 已落入本轮 Windows 的 TCP 排除范围 `49478–49577`，guest 可读而 Windows localhost 不通。只读采集排除范围后，将本轮 HTTP 端口换为 49470，随后 Windows localhost 与独立 Mac 均通过；没有删除系统端口保留或改 Windows 全局配置。TLS 49443/49444 不在该排除范围。旧端口失败与修正过程完整保留。
2. TLS 的 `Host: localhost`（包括显式端口）不匹配当前 Caddyfile 列出的 IP 站点，返回 Caddy 空 200，无 JSON/受保护内容、无上游 Via；这不是 manager 的免 token 成功。原先“任意伪造 Host 均必须状态 401”的采证断言过宽，保留首次失败后，区分“manager 返回 401”和“Caddy 未选中 manager 路由”。`Host: 127.0.0.1:49444` 与 Host+XFF 请求实际进入 manager 并返回 401。
3. 无关监听关闭后的第一次新鲜快照出现 firewall `available→unknown`，产品按保守契约将旧观测暂记 stale；重新采集恢复 available 后，同一历史观测重新 externally-verified。该中间失败保留，不把能力变化冒充单变量监听变化，也不将预期降级登记为 BUG-981 复发。
4. 采证脚本首次将错误 SNI 的预期异常写得过窄，只捕获 `SSLCertVerificationError`，而实际 Caddy 在发证前拒绝握手；修正为记录真实 TLS 错误后重跑。该修正只在忽略的检查点脚本，不改产品或门禁测试。
5. 初始化辅助脚本最初未向 `init` 子命令显式传 workspace，曾在本轮专属根额外创建辅助 manager；发现后以产品 stop_manager 停止，修正脚本并验证。没有落入或停止既有生产工作区。

# 对端（fenix-haier）网络安全测试总结

> 日期：2026-07-30
> 对端主机：fenix-haier `10.181.224.39`（局域网）
> 测试目标实例：`http://10.181.224.39:18002/`（经 Caddy 共享静态网关对外）
> 授权范围：用户自有局域网 lwa 部署的安全自检，非第三方目标
> 相关 task-list 条目：OPS-075（压测）、OPS-076（安全测试）、BUG-415、BUG-416

---

## 0. 总体结论

本次围绕对端 lwa 部署进行了 **三组测试**：

| 测试 | 视角 | 用例数 | 结果 |
|---|---|---|---|
| 一、阶梯抗压测试 | 性能 / 拒绝服务韧性 | 7 档（10→640 req/s） | ✅ 全档 100% 成功，无降级、无超时、无自愈异常 |
| 二、攻击面侦察 | 常见 Web 攻击向量 | 5 类 19 个探针 | ✅ 全部拦截（404 / 405 / 401），无敏感泄露 |
| 三、ZIP 导入攻击 | 恶意投递包 | 3 类（穿越/符号链接/炸弹） | ✅ 全部拒绝，零文件逃逸、零实例残留 |

**核心判断**：对端 lwa 部署的网关层（Caddy）、管理面（manager API）与导入层（zip_processor/security）三道防线在本次测试中均未被穿透。测试过程顺带发现两处**功能正确性**缺陷（BUG-415/416，浏览量统计漏计，非安全漏洞），已修复并回归。

## 1. 测试环境与目标拓扑

```
客户端(本机) ──LAN──> 10.181.224.39 (fenix-haier, 对端 lwa runtime)
                        ├── :8080   Caddy 共享静态网关根（对外提供静态内容）
```

## 2. 测试一：阶梯抗压测试（性能与 DoS 韧性）

### 2.1 方法
- 工具：自研 aiohttp 控速分发器（`/tmp/lwa_loadtest.py`，测试后已清理），按目标速率匀速发请求，分档执行，档间间隔 5s。
- 指标：成功率、p50/p90/p99/最大延迟，前后各做一次探活。
- 目标 URL：`http://10.181.224.39:18002/`。

### 2.2 阶梯与结果

| 阶梯 | 速率 | 成功率 | 延迟表现 |
|---|---|---|---|
| 第 1 档 | 10 req/s | 100% | p50≈6-7ms |
| 第 2 档 | 20 req/s | 100% | p50≈6-7ms |
| 第 3 档 | 40 req/s | 100% | p50≈6-7ms |
| 第 4 档 | 80 req/s | 100% | p50≈6-7ms |
| 第 5 档 | 160 req/s | 100% | p50≈6-7ms |
| 第 6 档 | 320 req/s | 100% | p50≈6-7ms |
| 第 7 档 | 640 req/s | 100% | p50≈6-7ms，p99<40ms |

- 全档 **100% 成功**，无 5xx、无超时、无连接拒绝。
- 即使 640 req/s，p50 仍稳定在 6-7ms、p99<40ms，无明显排队与降级。
- 压测期间 daemon 自愈（reconcile）未触发任何误启动/异常事件，实例状态稳定。

### 2.3 衍生发现（功能性，非安全）
压测后核查浏览量时发现统计异常，深挖定位两处缺陷（详见第 5 节）：
- 浏览量页面显示「1」实为 `uniqueIps`（按 IP 去重），非 `hits`（总命中）——属显示口径，非 bug。
- 但进一步分析发现 **BUG-415**（有别名静态实例的直连端口访问被丢弃）、**BUG-416**（日志轮转归档命名不匹配致丢行）。

## 3. 测试二：攻击面侦察（5 类常见 Web 攻击）

测试当天对对端复跑核对，下列均为实测响应码（`curl --max-time`）。

### 3.1 路径穿越（Path Traversal）

| 探针 | 响应 |
|---|---|
| `/../../../../etc/passwd` | 404 |
| `/..%2f..%2f..%2fetc%2fpasswd` | 404 |
| `/%2e%2e%2f%2e%2e%2fetc%2fpasswd` | 404 |
| `/static/../../../etc/passwd` | 404 |

**防御点**：Caddy 以实例 `webroot` 为 root，静态文件服务不把 `..` 解析到 root 之上；URL 编码变体同样被规范化后限定在 root 内。基线 `GET /` 为 200（约 12ms）。

### 3.2 敏感文件探测

| 探针 | 响应 |
|---|---|
| `/.env` | 404 |
| `/.git/config` | 404 |
| `/static-access.log` | 404 |
| `/run/pageviews.db` | 404 |
| `/../lwa.log` | 404 |
| `/api/instances`（经网关）| 404 |

**防御点**：对外 webroot 仅含站点静态资源；运行时目录（`logs/`、`run/`、`data/`、`lwa.log` 等）不在 webroot 路径下，无法经网关读取。

### 3.3 HTTP 方法限定

| 方法 | 响应 |
|---|---|
| OPTIONS | 405 |
| PUT | 405 |
| DELETE | 405 |
| TRACE | 405 |
| PATCH | 405 |

**防御点**：Caddy 静态服务仅放行 GET/HEAD，其余方法统一 405，杜绝写操作与 TRACE 反射。

### 3.4 CRLF 注入

| 探针 | 响应 |
|---|---|
| `/%0d%0aInjected:%20true` | 404 |
| `/x%0d%0aSet-Cookie:%20evil=1` | 404 |

**防御点**：Caddy 不把解码后的路径片段解释为响应头，无法注入 `Set-Cookie` / 伪造响应头。

### 3.5 管理面未授权访问

| 端点 | 响应 |
|---|---|
| `:17800 /api/instances`（无 token） | **401** `{"error":{"code":"unauthorized","message":"API token 无效或缺失"}}` |
| `:8080 /api/instances`（经静态网关） | 200（**SPA 回退**，非管理数据） |

**防御点**：
- 管理面 `:17800` 对所有受保护端点强制 token 鉴权，缺失/无效 token 返回 401 与统一错误体。
- `:8080` 上的 200 经与不存在的 SPA 路由对照，确认是静态站点 `try_files` 回退到 `index.html`，**并非管理 API 数据泄露**。

## 4. 测试三：ZIP 导入攻击（投递面）

> 说明：本组在**本地** lwa runtime 执行（与对端同源代码），因不可向对端注入恶意 zip。攻击包 `/tmp/lwa-sec-test/*` 测试后已清理。导入目标均为临时实例（非 `--update` 真实实例）。

### 4.1 攻击包构造

| 攻击包 | 体积 | 恶意成员 |
|---|---|---|
| `attack-traversal.zip` | 542 B | `../../../etc/lwa-escape-marker.txt`、`ok/../../evil2.txt`、`a/b/../../../../evil3.txt` |
| `attack-symlink.zip` | 248 B | 符号链接成员 `evil-passwd-link` → `/etc/passwd`（`external_attr=S_IFLNK\|0o777<<16`） |
| `attack-bomb.zip` | ~51 KB | `bomb.bin` = 50 MB 零字节，压缩比约 **1029:1** |

### 4.2 拦截结果

| 攻击包 | 命中防御层 | lwa 响应 |
|---|---|---|
| 路径穿越 | `audit_zip_members` → `zip_slip` | `[ZIP_IMPORT_ERROR] zip 成员安全审计未通过（zip_slip, zip_slip, zip_slip）`，清理半成品 |
| 符号链接 | `audit_zip_members` → `zip_symlink`（`S_IFLNK` 检测） | `[ZIP_IMPORT_ERROR] zip 成员安全审计未通过（zip_symlink）`，清理半成品 |
| 压缩炸弹 | `_assert_zip_bomb_safe`（>100:1 上限） | `[ZIP_IMPORT_ERROR] zip 压缩比过高（bomb.bin 约 1029:1 > 100:1），疑似压缩炸弹` |

### 4.3 逃逸与残留验证（关键）
- `find /etc /tmp /Users/... -name 'evil*.txt'` → **0 命中**；`/etc/lwa-escape-marker.txt` → 不存在。
- 工作区 `instances/sec-test-*` → 无残留目录。
- `lwa list` 回到测试前 4 个实例，无半成品泄漏。

### 4.4 导入层防御链（纵深）
1. `sanitize_zip_members`：解压前剥离冗余成员（node_modules/__pycache__/.git 等）。
2. `audit_zip_members`：对保留成员做 critical 级审计——`zip_symlink` / `zip_absolute_path` / `zip_drive_letter` / `zip_slip`（`..` 深度计数<0），命中即拒绝解压。
3. `_assert_zip_bomb_safe`：成员数 ≤50 000、解压总量 ≤2 GiB、单成员 ≤512 MiB、压缩比 ≤100:1。
4. 运行时路径包含校验：`resolve` 后必须在 `tmp_path` 内。
5. 解压后兜底扫描：`rglob("*")` 拒绝任何残留符号链接。

四层纵深无一被穿透，半成品实例统一自动清理。

## 5. 测试中发现并修复的缺陷

两处均为**浏览量统计的功能正确性**问题（非安全漏洞），由对端压测后的统计核查顺带定位：

### BUG-415：有别名静态实例的「直连端口访问」被整批丢弃
- **根因**：`pageviews.py` 构建 `alias_to_id`/`port_to_id` 时用 `if s.alias: / elif s.host_port:` 互斥填表，同时带别名+端口的 shared-static 实例只进 `alias_to_id`，其直连端口访问（`host:port/`，path 无别名前缀）端口匹配表查不到 → 被丢弃。
- **修复**：`elif s.host_port:` 改 `if s.host_port:`；别名前缀匹配优先命中后端口匹配被短路，不双计。
- **回归**：`test_ingest_all_counts_direct_port_for_aliased_static`。

### BUG-416：轮转检测只认 `.log.1`，不识别 Caddy `roll_size` 的 `-size.log.gz` 归档
- **根因**：`_read_new_lines` 轮转检测写死找 `static-access.log.1`（Caddy 实际产 `static-access-<ts>-size.log.gz`），命名不匹配致归档检测与补读双双失效；轮转后新文件增长越过旧 offset 时误判未轮转，跳过新日志。
- **修复**：新增 `_find_rotated_archive`（glob `<stem>-*-size.log.gz`，兼容 `.log.1`）+ `_archive_uncompressed`（gzip 自动解压），轮转检测与尾部补读改按未压缩字节 offset 比对；仅 `offset>0` 才查归档避免每次解压。
- **回归**：`test_read_new_lines_ingests_caddy_gzip_rotated_archive`。

两处均已修复并通过全部 pageviews 回归。

## 6. 防御体系评价

| 层级 | 防护机制 | 本次验证 |
|---|---|---|
| 网关层（Caddy） | root 限定、方法白名单（GET/HEAD）、路径规范化、无头注入 | 穿越/敏感文件/方法/CRLF 全拦 |
| 管理面（manager API） | LAN 绑定强制 token、统一 401 错误体 | 无 token → 401 |
| 导入层（zip_processor/security） | 5 层纵深（剥离/审计/炸弹/包含/扫描） | 穿越/符号链接/炸弹全拒、零逃逸 |
| 运行韧性（daemon/gateway） | 自愈 reconcile、健康探活、WAL | 640 req/s 无误启动/异常 |

总体评价：本次覆盖的攻击向量均被有效拦截，纵深防御设计在网关、管理、导入三处形成互补，单一环节失效不会导致整体被突破。

## 二、失败分类学与处置状态

1. **网络准入**（Docker Hub 裸连不可达、npmmirror 抖动、容器内安装不走代理）：Mac/Ubuntu 首轮的主要拦路虎。工作区构建代理（BUG-968～977、DEV-169）已在 main 实现并专项验收，**属未提交代码，三机实测快照不含**；需回三机复验；工作区代理只覆盖容器内安装及宿主前端，Docker daemon 拉基础镜像仍需单独配置，不能承诺所有网络故障消解。A05 Debian 首跑 ECONNRESET 为瞬时抖动，重试即过，不单列产品缺陷。
2. **宿主工具链**：pnpm 锁版本钉不住（A02，BUG-966→issue #145）、Node engines 双向不协商（A02 过旧失败于 Ubuntu A03 / 过新失败于 A07，BUG-967→issue #146）、corepack 缺失（Ubuntu，环境前提，已并入两条 issue 的提示口径）。
3. **容器工具链**：生成 Dockerfile 的 FROM 不按 engines 选 Node 大版本，A09 HedgeDoc（yarn 4.13.0 自带 + node:24-alpine）两机崩于 fetch 阶段 `onCancel`（CHK-477 待控制变量诊断：固定源码、锁、Yarn、镜像源与网络后对比 Node 版本；Mac 有构建后运行失败的独立记录）。
4. **产品缺陷（本轮新定案）**：AppleDouble `._*.py` 混入源码树破坏 Flask init-db 路径证明（A04 Debian，BUG-978→issue #144）。五步命令全过、状态仅「验证有警告」，业务断言（首页内容）不可省——这条是本轮最重要的方法论确认。
5. **应用边界（非缺陷）**：HedgeDoc 数据库方言需 `CMD_DB_URL`（CHK-425 历史口径：不新增配置出口，引导写 docker/.env.local）；构建成功后仍需单独完成应用特定数据库配置与业务验证。
6. **正确拒绝**：A08/A10 zip 符号链接审计、A11 pending 未确认形态拒启，三机一致，为相对 r2 伪成功的实质改进。

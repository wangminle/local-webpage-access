# BUG-1022 证书组替换中断恢复修复

范围：附件 P3 中仍待修复的入口证书组替换中断窗口。其他已修复的 P3 项未作扩展修改。

## 最终行为

- 更新 key/cert/meta 前，原子持久化包含完整旧内容、文件权限和缺失状态的私有恢复日志（0600）。日志不引用会在退出时清理的签发临时文件。
- 换入三份新文件后删除日志作为提交点；提交前中断尝试恢复旧组，KeyboardInterrupt/SystemExit 原样抛出。恢复再次失败时保留日志，不掩盖原始异常。
- 无清理退出后，下次持锁操作先按日志恢复，再读取元数据判断是否复用或重新签发。恢复会重复写入同一旧版本，直到全部完成才删除日志，因此可继续处理恢复过程本身的中断。
- 首次签发没有旧文件时，恢复删除未提交的新文件，再正常签发。损坏或不合法的日志不被覆盖，不把半提交材料当作有效证书。
- Caddy 冷启动和直接 reload 在读取证书前恢复，并持证书锁直至加载结束；恢复失败时取消加载，成功恢复后的 reload 使用 --force。同线程、同目录重入支持启动时重新渲染及签发。
- 新证书内容与目录变更按顺序刷盘。源文件以 r+b 打开，避免 Windows 刷盘要求可写句柄而导致签发失败；Windows 不以普通文件描述符刷目录。

## 验证

新增 `tests/scripts/test_bug1022_certificate_recovery.py`，30 项专项通过，包括真实 openssl 签发、公钥配对、CA 链、证书 SAN 与元数据一致性及私钥/日志权限：

- 首批修补前 11 failed / 4 passed；随后追加的恢复再次中断 3 项、Caddy 直接加载边界 4 项、锁重入 1 项和 Windows 刷盘句柄 1 项均先复现失败再修复。
- 真实子进程在日志发布、key/cert/meta 换入、恢复过程中和提交后执行 os._exit，不执行 except/finally；从持久化状态恢复，验证提交前回旧代、提交后留新代。
- 相关既有模块 66 passed / 2 skipped；另外显式启用 `LWA_RUN_CADDY_TLS_E2E=1` 的两项真实 Caddy 无 SNI TLS 集成，2 passed。
- 独立只读复核发现只读刷盘句柄的 Windows 兼容问题，修正为 r+b 后该项回归独立通过；最终复核无剩余阻塞发现。
- 最终 `bash tests/gate.sh`：4914 passed / 23 skipped（101.55 秒）；Ruff、工作区与暂存区 diff-check 通过。首轮一条既有前端构建测试在 builtin 端口 21007 健康检查失败，该用例独立重跑通过，最终门禁也通过；未据此修改无关业务代码。23 项跳过为显式 opt-in 的 Docker/TLS 测试，其中两项 TLS 已在上文单独启用验证。

Windows 句柄要求参考：[微软 FlushFileBuffers 文档](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-flushfilebuffers)。

## 最终保留的产品改动

| 事项 | 最终行为 | 主要位置 |

| BUG-943：中文 Windows 输出解码 | 根据 BOM 或交错 NUL 识别 UTF-16，否则严格尝试 UTF-8/GBK；解码失败保留 `unknown` / `decode-error`，避免把错误解码的空规则表当成有效观测。 | `platform_support.py`、`wsl_network.py` |
| BUG-944：WSL NAT 无 SNI HTTPS | 入口包含非 guest 本地地址时，网关与管理面共用工作区 CA 根直签的单张多 SAN 证书，覆盖回环、guest 与 Windows IP；证书写入 `run/tls/entry/`。新工作区可自举根证书；SAN、根指纹变化或剩余不足 400 天时重签，重签后强制 reload；签发互斥，缺 openssl 或失败时告警并回退。 | `static_gateway.py` |
| BUG-945：Debian Docker 安装冲突 | 仅在 Debian 的旧包清理列表补入 `docker-cli`、`docker-buildx`，避免与 Docker CE CLI / Buildx 插件文件冲突。 | `scripts/install-docker-linux.sh` |
| BUG-946：缺 Compose 时的数据救援 | 缺 `compose.yaml` 时仍按 manifest 的 project/service labels 严格查询 Docker；成功查空才视为无容器，旧容器继续救援；身份缺失或不匹配、查询失败、候选不唯一时中止。 | `docker_runtime.py` |
| BUG-947：Python 编译依赖与失败分类 | 从 requirements、pyproject 和 uv.lock 收集包名；uwsgi 安装前补 gcc/g++/make/libc6-dev。编译错误优先归为 `compile`，并过滤 BuildKit RUN 回显，减少把网络错误误判为编译错误；pip 失败提示区分网络与编译原因。 | `dockerfile_templates.py`、`build_diagnostics.py` |
| BUG-948：Node git 依赖 | package.json 或 yarn/pnpm/npm/bun 文本锁文件命中 git 依赖时，在安装依赖前补镜像内的 git。 | `dockerfile_templates.py` |

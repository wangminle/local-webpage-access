# V0.9.13 三机 11 样本生命周期

日期：2026-10-22。被测版本是已提交的 V0.9.13（`02696f90`）。Mac 与 Ubuntu 使用独立实验工作区。Debian WSL 的 SSH 横幅超时，样本没有执行。操作记录见 [检查点](../5-checkpoints/2026-10-22/three-host-lifecycle/README.md)。

每个样本的路径是：旧 zip 导入，启动，切旧文件夹，升新文件夹，切回旧文件夹，再升回新文件夹。

## 和上一轮比

上一轮可对照的事实是 r2（V0.9.8，Mac 与 Ubuntu）以及 2026-10-22 凌晨的 Debian 复跑（V0.9.9 之后的修复，A01–A07 与 A09 首页 200，A08/A10/A11 保持 pending）。

这一轮能确认变好的地方：

- Homarr 与 Memos 在 Mac 和 Ubuntu 上都停在 pending，`start` 被拒绝。r2 里这两类样本还能绕过待确认状态把源码或前端壳当成站点跑起来。这次门禁生效。
- Flaskr 在 Mac 上不开人工补丁就完成五步，首页标题是 Posts - Flaskr。Ubuntu 在补上 Docker Hub 代理后同样五步通过，标题相同。r2 的工厂命令引号和 instance 挂载问题没有再挡住这条路径。
- linkding 在 Mac 上五步通过，页面进入登录或书签跳转。Ubuntu 在代理可用后也能启动；其中一次切回旧文件夹构建失败时，旧版本继续服务，失败保护还在。
- Astro portfolio 在 Mac 上五步通过。r2 需要补 Node 工具链的那一侧，这次 Mac 自带的 Node 24 可以直接构建这个样例。

这一轮没有变好、或者换了一种失败的地方：

- IT-Tools 仍然起不来。Mac 上 corepack 带来的 pnpm 只接受 lockfileVersion 9.x，样本旧锁是 6.0。Ubuntu 上则是系统没有 corepack。
- Excalidraw 在 Mac 上因 Node 24 超出 engines `18–22` 失败。Ubuntu 因没有 corepack，还没走到 engines 检查。r2 靠引擎兼容配置才跑通，这次默认路径仍过不了。
- Uptime Kuma 在 Mac 上只要让 Docker 走本机 HTTP 代理就能完成五步。Ubuntu 上基础镜像拉下来之后，容器里的 `apk add` 不走该代理，挂满 1800 秒构建超时。
- HedgeDoc 在 Mac 上能构建并创建容器，随即因 Sequelize dialect 未设置而重启。LWA 写明没有确认应用消费 `DATABASE_URL`，所以没有注入。这和上次「要另给 `CMD_DB_URL`」是同一缺口。Ubuntu 上 Yarn 安装在镜像源拉取阶段失败。
- FastAPI Template 这次没有进入 pending 判断。zip 里的符号链接被安全审计拒绝。工作区副本中的链接指向本机 `.venv`，不能把这次失败写成产品误判。
- Debian 上次已经有八个样本首页 200。这次机器连不上，无法证明那些结果是否还在，也不能做新版本复验。

从这台 Mac 能打开的，是 Mac 上的 2048、Astro、Flaskr、linkding、Uptime Kuma，以及 Ubuntu 上的 2048、Flaskr、linkding。不是 11 个都生成了，Debian 一个都没有。

整体看，V0.9.13 把「未确认形态不得启动」和 Flask / linkding 的启动路径做实了。包管理器版本、Node engines、容器内下载代理、HedgeDoc 的数据库方言，仍然要人工环境或额外配置。Docker Hub 在这两台机器上都不能裸连，必须指到各自本机代理的正确端口。

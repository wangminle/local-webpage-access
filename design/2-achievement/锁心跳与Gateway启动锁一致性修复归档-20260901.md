## 2. BUG-606：锁心跳载荷一致性

### 2.1 问题

`_touch_lock_heartbeat` 原先采用 `seek → truncate → write` 原地刷新锁文件。并发读者可能在 `truncate` 与 `write` 之间读到空文件或单行载荷，导致测试偶发 `IndexError`，锁状态诊断也可能短暂退化。

核心文件锁仍绑定同一 inode，因此该缺陷不破坏互斥本身，但会污染锁状态观测并造成测试门禁不稳定。

### 2.2 设计与实现

1. `_touch_lock_heartbeat` 复用 `file_lock.write_lock_payload`，在同一 inode 上先写入完整载荷，再按新长度截断并同步，不再先清空文件。
2. `lifecycle._read_lock_payload` 统一解析 PID/时间戳，对空内容、单行或非法载荷做最多三次有界重读。
3. 持续单行但 PID 合法时保留 PID 并返回零时间戳，让既有 mtime 逻辑兜底；完全无效时安全降级为无载荷。
4. `_lock_timeout_message` 与 `_lock_is_stale` 统一复用该读取器。
5. 保持 inode 不变，不使用 `replace` 或 `unlink`，继续满足 BUG-213 的跨进程互斥约束。

### 2.3 验证

- 确定性覆盖真实 `os.ftruncate` 边界，证明截断发生前完整载荷已经写入。
- 覆盖首次不完整后重读成功、持续单行 PID 兜底、持续无效安全降级。
- 2026-09-01 重新运行 `tests/test_lifecycle.py` 与 Gateway 锁专项组合，退出码为 0。
- 相关 Python 文件通过 ruff 与 mypy。

## 3. Issue #26：Gateway 启动锁与双 Caddy master 竞态

### 3.1 初始事故与第一阶段修复

update 重启编排期间，新 daemon 的 `ensure_caddy_running` 可能在 Gateway 监督器 `start_gateway` 的同时执行 `caddy start`。Caddy 的 `SO_REUSEPORT` 允许两个 master 同时监听 `:8080`/`:2019` 并共享 pidfile；先退出者删除 pidfile后，监督器会继续误判网关掉线。

第一阶段修复将以下路径统一纳入 `gateway_start_lock`：

- `start_gateway`；
- `StaticGateway.ensure_caddy_running` 的离线拉起路径；
- `stop_gateway_internal`；
- update 重启后的单 master 检查。

同时将 `caddy start` 的 stderr 追加写入 `logs/caddy-runtime.log`，并在 update 收尾使用 `lsof` 检查 `:2019` 的监听 PID 数量，以弥补探活、waitReady 和 doctor 无法识别双健康 master 的盲区。

### 3.2 复审发现的跨线程自阻塞

第一阶段候选用普通线程锁保护“检查重入状态 + 等待 `flock`”过程。等待线程持有进程互斥锁等待 `flock` 时，原持有线程又需要同一把进程锁才能进入 `finally` 释放 `flock`，形成同进程跨线程自阻塞。

最小复现表现为：线程 A 原计划短暂持锁，线程 B 却一直等待到超时并抛出 `LifecycleError`，A 才能释放文件锁。

### 3.3 最终方案 A

1. 进程内协调锁改为 `threading.RLock`，并覆盖获取 `flock`、业务 `yield`、释放 `flock` 的完整临界区。
2. 同线程重入时 RLock 可重入，由线程本地 depth 判断嵌套层级，仅最外层获取和释放 `flock`。
3. 不同线程先在 RLock 上排队，当前持有线程可以无阻碍进入 `finally`；随后等待线程再获取自己的 `flock`。
4. RLock 等待与 `flock` 等待共用同一个 deadline，保持原有超时预算和 `LifecycleError` 契约。
5. 接受同一进程内不同工作区的 Gateway 启停被全局 RLock 串行化；LWA 服务进程以单工作区运行为主，该取舍比引入按路径锁表更小、更稳。

### 3.4 验证

- 新增不同线程先后成功进入临界区的回归测试，事件顺序为持有者进入/释放后等待者进入/释放。
- 保留同线程嵌套重入、跨 fd/跨进程互斥、锁超时 fail-safe、停止路径持锁等回归。
- 覆盖 `ensure_caddy_running` 持锁拉起、等待后认领其他持有者启动的 master、配置锁场景短超时有界化。
- 覆盖 update 单 master 检查、PID 去重和 Caddy stderr 落盘。

- 相关 Python 文件通过 ruff 与 mypy。

# Win11 / WSL 软件包 3.x / Debian mirrored 本机验证

日期：2026-10-22。对应 PLN-054 的 **M11-3 部分实机验收**，不是全部组合或独立局域网访问通过声明。

## 环境与范围

- 基线：`8e4f99c`（V0.9.12-Build5406-20261022）；本轮另外修复 BUG-949、BUG-950，尚未提交。
- Windows 11 专业版 Insider Preview，完整版本 `10.0.28020.3262`。
- WSL **架构为 WSL2**，软件包 `3.0.4.0`，Linux 内核 `6.18.54.1-microsoft-standard-WSL2`。
- Debian GNU/Linux 13.7，systemd 运行；`.wslconfig` 声明与 `wslinfo --networking-mode` 实测均为 mirrored。
- 验证使用 Linux 文件系统中的独立源码、Python 3.13.5 虚拟环境、工作区和测试端口；依赖按仓库 `uv.lock` 版本约束安装，`pip check` 通过。Caddy 2.11.7 与项目 CI 一致，下载制品按官方校验文件验证。
- 未变更 Windows 防火墙、portproxy、网卡或 WSL 配置；未重启 WSL/Windows，未安装系统自启或系统 CA 信任。HTTPS 客户端显式指定本轮工作区 CA。

## 已成立的实机结果

| 验证项 | 结果及证据边界 |
| --- | --- |
| 模式与版本识别 | 正确区分 WSL2 架构与 3.0.4.0 包版本；识别 Win11、mirrored；七项只读采集能力均 available |
| 多网卡与入口 | 同时存在物理网卡、虚拟网卡及 VPN 接口；按默认路由选择物理 WLAN；guest 与 Windows LAN IP 一致。portproxy 为空，mirrored 不依赖该规则 |
| CLI / API / doctor | 静态实例 running；CLI、管理 API 和 doctor 保持 `candidate-unverified`；未取得外部证据时不报已从外部验证 |
| HTTP，Debian 内 | 实例直连与路径别名成功；页面、相对 CSS、JS 均为 200，内容哈希与样本一致 |
| HTTP，Windows localhost | 实例直连及路径别名的页面、CSS、JS 均为 200，哈希一致 |
| HTTPS，Debian 内 | localhost 与 guest 持有的 LAN 地址均可通过证书验证；页面、相对 CSS、JS 为 200，哈希一致 |
| HTTPS，Windows localhost | 页面、CSS、JS 为 200，哈希一致；显式 CA 校验通过；未导入 Windows 系统信任库 |
| CA 反向验证 | Debian 客户端不指定工作区 CA 时证书链校验失败，未使用跳过证书验证 |
| HTTPS 明文旁路 | 隔离工作区设置 `instanceBindHost=127.0.0.1` 并重启实例后，直连口与管理后端均仅监听回环；Debian 按 LAN 地址访问实例明文口、管理明文口、旧 HTTP 别名口均连接拒绝，HTTPS 页面和管理面仍可用。仅 reload 网关不会重写已有实例的绑定配置，需重启实例使设置生效 |
| 管理鉴权 | Debian 经 LAN 地址访问 HTTP/HTTPS 管理 API，无 token 为 401，有效 token 为 200；伪造回环 Host/XFF 仍为 401。localhost 的只读请求按既有本机策略为 200。这里仍不是另一台物理设备的验收 |
| Windows 自身 WLAN 地址 | HTTP 与 HTTPS 测试端口均超时；仅记录该观察位置的失败，不推导另一台 LAN 设备的结果或断言单一根因 |
| doctor 完整性 | BUG-950 修复后能输出完整 JSON；版本检查为 SKIP。overall 仍为 FAIL，因本 Debian 的 Docker/Compose 不可用，不写成整机健康通过 |

首次 TLS 管理 API 的 5 秒探测预算曾超时；复验使用 20 秒预算，冷请求约 12.5 秒、后续请求约 0.02–0.05 秒。该响应耗时观察保留，不把第一次超时改写成始终快速通过。

## 独立局域网客户端复验（同日补充）

按用户指定的 SSH 别名连接另一台 Linux 物理设备，由该设备经物理 WLAN 直连 Debian 的 LAN 地址；没有建立 SSH 端口隧道、代理或额外组网。分 HTTP 与 HTTPS 两阶段重新启动同一隔离工作区，各阶段先确认 Debian 本机页面内容正确。

| 远端检查 | 结果 |
| --- | --- |
| 路由与二层邻居 | 走同一物理局域网；能解析 Windows WLAN 的 MAC，ARP 邻居为 REACHABLE。ping 无应答，仅作为附加观察 |
| HTTP 实例直连、路径别名 | 两种入口的页面、CSS、JS 全部连接超时；对应 TCP 连接亦超时。HTTP 阶段已确认实例、别名和管理监听均对外绑定 |
| HTTP LWA 管理页 | 管理首页及 API 全部连接超时；请求尚未进入 token 校验阶段 |
| HTTPS 页面与 LWA 管理页 | 两个 TLS 入口均 TCP 超时，页面、CSS、JS、管理首页及 API 不能取得。客户端已准备通过内存显式加载工作区 CA，但连接未到达 TLS 握手阶段，不能记作证书通过或失败 |
| 只读网络策略 | WSL Hyper-V 防火墙已启用、默认入站 Block、出站 Allow、回环启用。该现象与入站受阻一致；没有定位到具体丢弃规则，不断言唯一根因 |

结论：**当前环境从另一台物理 LAN 设备不能访问这些测试网页和 LWA 管理入口**。服务本机可用不等于 LAN 可用；M11-3 继续保持部分通过。未修改 Windows/Hyper-V 防火墙、转发、WSL 全局配置或远端系统信任。

新增原始证据保存在本地检查点的 `remote-lan/` 子目录，含远端路由/ARP、HTTP/HTTPS 逐请求结果、Debian 监听和 Windows 防火墙只读快照。独立设备的真实地址及 SSH 接入信息不写入公开材料。

## 发现并修复

- **BUG-949**：CLI 把 mirrored 的无转发候选统一写成“已发现转发”。移除这段无证据说明，保留“尚未从其他设备验证”。
- **BUG-950**：editable 安装可定位无 `.git` 的源码，版本检查在取仓库锁时抛异常，导致整份 doctor 中断。对取锁的 `SourceUpdateError`、`OSError` 降级 SKIP；已有锁忙处理保持不变，不创建伪 Git 元数据或成功缓存。

新增三项回归先复现失败再修复。最终在本 Debian 中运行九个相关测试模块，**446 passed / 0 skipped / 0 failed**，包含显式启用的真实 Caddy 无 SNI TLS 握手测试；Ruff 与 Git 差异检查通过。未运行完整项目门禁，未启用真实 Docker 用例。

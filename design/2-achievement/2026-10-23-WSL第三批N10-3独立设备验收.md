# WSL 第三批 N10-3 独立设备验收

日期：2026-10-23。关联 PLN-054、BUG-980、BUG-981。目标是补 Win10 NAT 的真实 LAN 证据；Win11 按用户安排跳过，在另一台机器依此记录续跑。

**结果：独立 Mac 经真实 Windows 入口访问 HTTP/HTTPS 页面、资源与有状态容器成功；管理鉴权发现 P1 缺陷，整体验收未通过。** 主要版本组合与宿主恢复矩阵仍未完成，不关闭 PLN-054。

## 环境与隔离

- Windows 10 Pro 22H2 / Build 19045.6456，WSL 软件包 3.0.3.0、WSL2 架构，Debian 13.7，实际运行模式 NAT。
- 隔离源码为 HEAD `02696f9` 加当前待提交修复；源归档 SHA256 为 `48d167eca73abd3a82b43f37d9af0de556e9a35070c8b9533bb78f495256fbc6`，补丁指纹 `04ef4b90c2df37f53b8b43418a030ad3a40db6c1a161bdf1d19143468cfb12ac`，共331个文件。逐文件哈希保存在原始检查点，不能把本轮结果归给纯 `02696f9`。
- 新建独立工作区、测试端口、静态实例与零第三方运行依赖的 Python/SQLite 容器；没有把生产或已有 Eval 工作区用作测试夹具。该容器验证网络与持久化机制，不冒充11个真实项目的业务验收。
- Windows SSH 令牌没有提权。管理员手工执行审阅后的临时 portproxy 与防火墙脚本：仅测试端口、仅独立 Mac 来源、转发到 Windows 回环地址；LWA 产品没有修改 Windows 网络。
- Mac 走物理局域网直连 Windows 地址，无 SSH 隧道，无应用代理。HTTPS 仅加载测试工作区公共 CA 到单次客户端，不修改系统信任，不忽略证书错误。

真实地址、SSH、原始命令、源码冻结、资源哈希与请求响应仅保存在忽略目录 `design/5-checkpoints/2026-10-23-wsl-n10-acceptance/`。

## 新缺陷与验收判定

[BUG-980问题与复现](../4-issues/2026-10-23-WSL回环转发管理鉴权缺口.md)：Windows回环转发丢失来源，peer与Caddy生成的XFF都可能是回环；再相信可伪造Host/同源头会使外部请求免token。本轮使用只读能力API与故意不存在的实例验证，无真实业务写操作。

因此本轮仅将“网页/资源可达、TLS身份、代表容器数据与进程恢复”分项记为通过。鉴权修复及同路径复验是 N10-3 收口前置条件，页面200不构成整体验收。

## 观测记录、撤销与清理

实测内容匹配后通过产品 `access record-observation` 记录 lan-client / https / content-match / 200 与实际URL，即时升格 `externally-verified`。第一次随后采集的TCP监听从unknown恢复available，指纹变化导致记录保守失效；保留该事实，不能将这次降级说成已执行guest地址变化或Windows重启。

测试应用已停止：两实例、网关与manager均关闭，隔离daemon关闭，临时systemd单元已移除；仅本轮容器及其镜像标签已删除，WSL测试端口无监听。保留隔离源码、数据、CA和证据以便复现，不安装到系统信任。

清理前后核对：三个既有工作区配置SHA256相同，原有8个容器的ID、名称和端口集合一致，生产管理服务health正常。源码归档中的159个产品源码文件复核无变化；不是把全部331个归档文件都声称逐项重验。

管理员随后执行原脚本 `-Action Remove`，回执为仅本轮归属规则已删除。独立只读复查确认：三条测试portproxy不存在、对应防火墙持久化规则不存在、归属记录已删除；原有两条SSH转发的监听和目标保持不变。当前SSH令牌的防火墙CIM枚举报Access denied，未误记为规则为空；改由可读取的Windows持久化注册表核对本轮规则，与管理员成功回执互证，不宣称枚举了全部活动防火墙策略。

Mac直连三个测试端口均失败；产品新快照报告 `entry-missing`、`lanObservationStale=true`，历史观测仍保留。此时测试应用此前已经停止，因此不把连接失败或本次指纹变化写成仅由规则撤销造成的严格单变量转移；规则删除本身由注册表独立证明。三个既有配置哈希、原8个容器与生产health再次核对正常。本轮测试和清理执行完成，BUG-980/981及整体验收保持未完成。

第二次采集两侧TCP监听均available，但仅一个无关Windows回环高位端口消失，指纹的所有非监听片段完全相等，管理API仍将刚记录的外部证据判为过期。已另记 [BUG-981](../4-issues/2026-10-23-WSL无关监听导致外部观测失效.md)；不能将该次误失效当作网络切换验证通过。

## 另一台机器的续验顺序

1. 先处理BUG-980并锁定修复后源码指纹；在另一台机器创建独立工作区和全新测试端口。记录Windows Build、WSL软件包号、发行版、实际模式、Docker后端，不能只写“Win11/WSL3”。
2. 先留WSL、Windows本机与独立LAN客户端的负向/正向基线；mirrored的Hyper-V防火墙和Windows入站原因保持只读定位，必要处置由管理员审阅后执行。
3. 分HTTP与HTTPS核对HTML/CSS/JS内容、浏览器动作、真实容器数据、管理页面、无/有效/伪造token与Host/XFF/同源头。证书需校验实际入口身份，不加载CA必须失败；检查管理后端和实例明文旁路。
4. 记录真实LAN成功后核查CLI/API/doctor的观测展示，再在受控撤销入口后确认失效。不要把模拟、多网卡夹具或隧道请求记为真实LAN通过。
5. 维护窗口另跑休眠恢复、WSL关闭重开、guest地址变化、Windows重启与自启。每项前后比较地址、规则目标、服务/容器状态、数据、CA与观测新鲜度。当前Win10未安装LWA自启单元、linger关闭，不能直接期待重启后服务自启。
6. WSL包2.x、Win11 NAT、其他主要组合没有现成环境则保持待测；不得在承载业务的当前机器上为凑矩阵升级/降级或强制切换网络模式。

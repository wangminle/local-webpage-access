# HTTPS 首版交付 WBS（20260918）

> 依据：CHK-352 审查（design/5-reviews/2026-09-17-agent-m1-readiness-https-review.md §3）把 HTTPS 从远期 P2 提前；
> 承接 design/3-plans/2026-09-16-LAN与Agent访问安全加固方案.md 路线 B（H1-B1~B5），按审查修订：
> **管理面不再沿用同源 `/manager/`**（H1-B5 原案作废），改为独立 HTTPS 端口 origin。
> 目标：保护现有 LAN 管理凭据与应用登录，不等 M2 全部完成。

## 0. 首版交付边界（审查四项）

1. 管理面独立 HTTPS origin（独立端口，非同源路径）；
2. Caddy internal CA：存储归属/持久化/权限明确，根证书导出+指纹，客户端信任验证，错误证书必须拒绝；
3. manager 与实例直连明文入口同批收敛（Docker 发布、IPv6、重启迁移）；
4. URL 生成、探活、CLI/管理页、反代鉴权与故障回退适配——TLS 失败不得静默回退 HTTP。

**非目标**：远程 Agent 开放（仍需 M2 独立身份/scope/验收）；builtin 网关 TLS（http.server，支持矩阵明确不支持）；ACME 公网证书。

## 1. 关键设计决策

- **D1 管理面独立 origin**：Caddy 新增站点块 `https://127.0.0.1:{managerTlsPort}, https://{lanIp}:{managerTlsPort}` → `reverse_proxy 127.0.0.1:{managerPort}`。独立端口构成独立 origin（Cookie 隔离语义按 host:port，审查提示端口不隔离 Cookie——故 manager 侧凭据仍是 Bearer token，不引入 Cookie 会话，端口隔离仅用于 origin 区分与路径不混布）。
- **D2 CA 归属**：Caddy master 由 LWA spawn 时注入 `XDG_DATA_HOME=<ws>/run/caddy-data`、`XDG_CONFIG_HOME=<ws>/run/caddy-config`——internal CA（`pki/authorities/local/root.crt`）落工作区、随 workspace 迁移/备份、权限 0700。根证书指纹 = SHA-256(CRT DER)。
- **D3 支持矩阵**：`gatewayTls` 仅在 `staticGateway=caddy` 时可开启（config 校验拒绝 builtin+TLS）。TLS 开启时明文入口默认关闭（`gatewayPlainPort=None`），可选配置保留（文档标注非安全边界）。
- **D4 证书 SAN**：站点地址显式列 `127.0.0.1` + 当前 LAN IP（Caddy internal CA 为 IP 站点签 IP SAN 证书）；LAN IP 变化经 `lwa access refresh` / gateway 重启重生成 Caddyfile。
- **D5 明文收敛**：`instanceBindHost`（默认 `0.0.0.0` 兼容）→ builtin `--bind`、Caddy 站点块地址、Docker `ports: "{ip}:{h}:{i}"`；`gatewayTls=internal` 时 manager 绑定强制 `127.0.0.1`。回环上游（别名反代、探活）保持明文 HTTP——收敛目标是"明文只存在于回环"。
- **D6 反代鉴权**：TLS 模式下 manager 信任唯一反代（本机 Caddy）。回环免鉴权判定增加 X-Forwarded-For 链校验：存在 XFF 且链中任一地址非回环 → 按远程对待（防伪造 Host+经反代冒充本机）。不开启 uvicorn proxy_headers（保留 peer 真实性，自行解析）。
- **D7 探活证书验证**：https URL 探活用 ssl.Context（CA 系统库 + LWA root.crt），验证失败即失败——禁止 verify=False。服务器本机对 127.0.0.1 的 https 探活同样走证书验证（IP SAN 覆盖）。

## 3. 验收清单（两台设备，人工）

1. 客户端 A/B 安装 root.crt 后 `https://<lan-ip>:8443/<alias>/` 与 `https://<lan-ip>:9443/`（管理页）无告警；
2. 未安装根证书的浏览器得到硬告警，且按 docs/https.md 可完成安装；
3. 明文拒绝：TLS 模式下 `http://<lan-ip>:8080`（默认关）、`http://<lan-ip>:17800`（manager 回环化）不可达；
4. 无旁路：`instanceBindHost=127.0.0.1` 时 LAN 扫描仅剩 SSH 与 8443/9443（注意 Docker 发布绕过 ufw 的官方告诫——以实际扫描为准）；
5. 重启/回退：`lwa services restart` 后 TLS 入口恢复；证书删除/损坏时 gateway 启动显式报错，不降级 HTTP；
6. 管理页经 https 反代可用（token 正常），XFF 伪造 Host 的回环冒充被拒。

## 4. 风险与后续

- LAN IP 变更需重生成 Caddyfile（access refresh 联动，文档注明）；
- `gatewayPlainPort` 保留时明文面仍在（默认关，文档标注非安全边界）；
- 远程 Agent 仍关闭：待 M2 独立身份、scope/实例 ACL 与远程协议验收（CHK-352 §3.5）。

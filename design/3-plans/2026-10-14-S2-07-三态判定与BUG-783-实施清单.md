## 1. BUG-783 根因与方案取舍

### 根因

- 所有工作区的 Caddy master 默认把 admin API 绑在同一点 `127.0.0.1:2019`；
  Caddy 的 SO_REUSEPORT 允许第二个 master 同样绑成功（双 master 并存）。
- `caddy reload --address 127.0.0.1:2019`（即 `POST /load`）**推送目标是"谁在 :2019 上听"
  而不是"本工作区的 master"**。BUG-176 只给 `POST /stop` 加了归属校验，
  reload/stop 不对称。
- 已删除工作区的孤儿 daemon（旧代码）reconcile 时走 reload 路径，
  把"自己（已不存在）工作区"的空配置推到共享 :2019，真实工作区的运行配置被清空
  （2026-10-13 20:20–20:23，8080/8443 全断）。
- 注意：客户端 reload 前的归属检查（IMP-033）在 SO_REUSEPORT 双 master 下不可靠——
  检查探针与 reload 请求可能落到不同 master；且孤儿进程跑的是旧代码，
  不会执行新加的客户端检查。**任何"推送前再校验一下"的方案都无法约束旧代码孤儿。**

### 候选方案对比

| 方案 | 侵入面 | 能否阻断旧代码孤儿 | 结论 |
| --- | --- | --- | --- |
| A. 每工作区独立 admin 端口（运行时分配并登记，Caddyfile 写 `admin 127.0.0.1:<port>`） | 中：static_gateway / gateway_service / doctor / autostart / updater / cli 的 admin 地址收口 | **能（结构性）**：真实工作区升级后 master 不再监听 :2019，旧孤儿推 :2019 只会打到它自己/ nobody | **选用** |
| B. 加载请求携带工作区身份校验 | 小 | 不能：Caddy admin API 无原生鉴权可挂；且旧代码孤儿不执行新检查 | 否决 |
| A+B 组合 | 大 | 能 | 留作后续加固，本期不做 |

### 方案 A 设计要点

- 新模块 `admin_port.py`：
  - `LEGACY_ADMIN_PORT = 2019`；分配区间 **20201–20500**（避开并行测试占用的 21000–21050）。
  - 分配物化在 `run/admin-port`（原子 O_EXCL 创建；已存在则直读）——即"运行时分配/登记"。
  - 候选端口 = `20201 + sha256(工作区根路径)[0] % 300`；候选被占用则顺序后移。
    不同工作区默认错开；冲突时后分配者顺延，登记文件保证稳定。
  - `read_admin_port(ws)`（未分配返回 None，调用方回退 2019，**未启动过的工作区行为与旧版完全一致**）；
    `ensure_admin_port(ws)`（reload/start 路径调用）；`admin_base(ws)` / `admin_address(ws)`。
- `StaticGateway` 收口：`_admin_alive` / `caddy_stop` / `_reload_once --address` /
  `_admin_holder_pid`（lsof 探的是分配端口）全部走分配端口（未分配回退 2019）。
- 主 Caddyfile 全局选项块增加 `\tadmin 127.0.0.1:<分配端口>`（未分配不写，兼容旧测试）；
  bootstrap 最小配置同样带 admin 指令，保证冷启动 master 绑对端口。
- **迁移逻辑（平滑升级）**：`caddy_start` 在拉起新 master 前，若已分配端口 ≠ 2019 且
  legacy :2019 仍在线：按 BUG-176 同款校验（caddy.pid 存活 + 命令行含本工作区路径）
  确认是本工作区旧 master → POST /stop 停掉它再启动新 master；
  不归本工作区则告警但不替用户停（维持 fail-closed 语义边界）。
  `caddy_stop`（`lwa gateway off`）对称处理：分配端口 + legacy 端口都尝试停。
- 波及面：`gateway_service.is_gateway_running` / start_gateway 文案、
  `updater._check_single_caddy_master`（改为按工作区分配端口数 master）、
  `doctor.check_caddy_health` / `check_port_contention`（探分配端口，未分配回退 2019）、
  `autostart._port_2019_foreign`（探分配端口）、`cli/gateway.py` 提示文案。
- `run/gateway.json` 的 `admin_port` 字段改为写实测分配端口（该字段本就为此预留）。

## 2. S2-07 三态判定设计

- 新模块 `ownership.py`：`class Ownership(Enum): OURS / FOREIGN / UNKNOWN`。
- `hosting._gateway_holds_static_port(...) -> Ownership`：
  - 确证不持有（admin 不在线 / 片段不绑端口 / builtin pid 死或命令行不符 / 监听者身份不符）→ `FOREIGN`；
  - lsof 不可用（监听者身份不可见，旧代码的 `names is None → True` 放行路径）→ `UNKNOWN`；
  - 证据链完整（caddy 在监听名单 / builtin python 在名单）→ `OURS`。
- `autostart._port_2019_foreign(ws, config) -> Ownership`（探测对象为本工作区分配 admin 端口，未分配回退 2019）：
  - json 态 / live pidfile / admin owner 任一证实本工作区持有 → `OURS`；
  - admin 在线但非本工作区，或端口可连且无本工作区证据 → `FOREIGN`；
  - 各探测异常且端口连通性也不确定（非 ECONNREFUSED 的失败）→ `UNKNOWN`，并收集各探测异常。
- 处置语义：
  - 静态端口 `UNKNOWN`：**维持放行（复用）但写事件** `port_ownership_unknown`；
    doctor 在 lsof 缺失时给 WARN「归属未确认（缺少 lsof）」（`check_port_contention`
    由 SKIP 升级为 WARN）。
  - admin 端口 `UNKNOWN`：**仍然阻断**（不能去启停可能属于其他工作区的网关），
    文案改为「无法确认 :<port> 归属」，列出各探测异常，不再说「被外部占用」；
    `FOREIGN` 保留原有「已被外部 Caddy/进程占用」文案。

## 3. 全库同类判定盘点与处置表

全库 grep `is None: return True` 与 `except Exception: pass` 后紧跟判定的写法，逐条归类：

| 位置 | 写法 | 判定去向 | 是否影响用户决策 | 处置 |
| --- | --- | --- | --- | --- |
| autostart.py `_port_2019_foreign` | 三段 `except Exception: pass` 后 socket 判定 | autostart caddy 检查 FAIL/放行 | **是**（误判会诱导用户杀自家网关或放行占用） | **本包改**：三态 + 异常上屏 |
| hosting.py `_gateway_holds_static_port` | `_listen_process_names` 返回 None（lsof 缺失）时放行 | 端口复用/重分配 | **是**（UNKNOWN 时用户看不见不确定性） | **本包改**：三态 + 事件 |
| hosting.py:2597 / docker_runtime.py:355 | 取消标志读取吞异常 → 视为未取消 | 构建取消 | 否（漏一次取消轮询，下轮重读） | 不改 |
| gateway_service.py:716/730/749/782 | stop 路径清状态/清 pid 吞异常 | 网关停止收尾 | 否（已是 best-effort 收尾，有日志） | 不改 |
| manager_service.py:907/955/1155 | 停服清缓存/清状态吞异常 | 管理页停止 | 否 | 不改 |
| build_queue.py:104/1183 | gate 清理/注册吞异常 | 构建并发闸 | 否 | 不改 |
| logging.py:218 | 日志初始化吞异常后回退默认 | 日志落盘 | 否（有后续报错路径） | 不改 |
| static_gateway.py `_admin_alive` 等探测 | 探测吞异常 → 不在线 | 归属/健康判定 | 部分（已由 inspect_caddy_owner fail-closed 兜底） | 不改 |

结论：影响用户决策的项即本包已列入的两处；其余保持现状，避免扩大行为变化面。

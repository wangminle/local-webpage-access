# S3-04 实施清单：操作时间线（DEV-160 / issue #59）

> 依据：WBS §5 S3-04。前置：S2-08（操作来源）、S2-02（lastOperation）。

## 目标

按时间倒序合并生命周期事件、构建记录与最近一次操作态，并标注发起方；管理页详情与 CLI 均可查看。

## 实施步骤

1. [x] schema v8：`events` 增加 `source` 列（存量为 NULL）；`CURRENT_SCHEMA_VERSION` 7 → 8。
2. [x] `registry/dao.py`：`add_event(..., source=None)`，缺省取 `current_op_source()`（cli/manager/daemon/agent），调用方无需逐处改动。
3. [x] `timeline.py`：`build_timeline(registry, iid, last_operation=, limit=)` 合并三类记录；
   构建行附 `durationSeconds`；无时间戳的条目跳过；历史事件来源显示 `unknown`；`format_timeline_lines()` 供 CLI 复用。
4. [x] API：`GET /api/instances/{id}/timeline?limit=`（1–200，默认 50）；实例详情响应新增 `timeline`（只增字段）。
5. [x] CLI：`lwa logs <id> --timeline`（`--tail` 为条数）。
6. [x] 管理页：详情新增「最近操作」区块（前 12 条，标注来源、耗时）。
7. [x] 测试 `tests/scripts/test_s3_04_timeline.py`（12 例）：schema v8 与列存在；来源默认值与显式覆盖；
   合并排序（固定时间戳，断言 operation → build → event）；历史来源 unknown；limit 与无时间戳跳过；
   文本行格式；API 合并、详情字段、404、limit 校验；CLI 输出与未知实例退出码。
8. [x] 回归：`test_agent_store.py` 三处 schema 版本断言 7 → 8。
9. [x] 文档：`docs/manager-page.md`（最近操作）、`docs/agent-guide.md`（timeline 端点）、`docs/operations-playbook.md` §6.1。

## 偏差与未做

- WBS 与 DEV-160 提到“阶段耗时”。本期只对构建行与 lastOperation 提供总耗时；`lifecycle_stage` 事件之间的分段耗时未做（事件只记录阶段名，不记录起止点，需要另行设计）。
- 时间线只读，不做分页游标；`limit` 上限 200。

# WSL 第三批实机验收执行计划

> 沿用已确认的 WSL 跨版本适配草案及用户本轮选择，按实机验收与用户文档推进。所有改动保持未提交；本计划不创建分支、不改变现有支持门槛。

**目标：** 补齐可获得环境的第三批证据，逐项列明完成、失败、环境阻断与待人工执行；不把模拟或历史结果替代本轮实机证据。

**方式：** 复用现有能力，在用户级独立测试工作区和专用端口准备页面及服务；从 WSL、Windows 本机和独立 LAN 控制机逐层检验 HTTP/HTTPS、资源内容与管理鉴权。原始接入和日志仅保存在已忽略的检查点目录。保留现有 BUG-949/950 等未提交改动。

## 任务与核验

1. [x] 环境盘点：核对当前提交、预存改动、已登记 SSH 目标和网络模式；版本组合不具备时记待测，不安装或切换 WSL。
2. [x] N10-3 本轮可执行范围（独立 LAN 正向仍未通过）：复读中文 Windows portproxy，确认已有 SSH 规则可见；隔离工作区验收页面/CSS/JS、HTTPS 多 SAN 与客户端信任/鉴权；从当前独立物理设备直连 Windows 入口，失败保留位置与原因。
3. [ ] M11-3 及其余组合：可访问时复用隔离环境补独立设备 HTTP/HTTPS、鉴权与明文旁路；只存在历史材料时标历史部分完成，新增组合不得由模拟填充。
4. [ ] 恢复场景：准备变更前后采证、缓存与地址刷新核查清单；可安全模拟的产品缓存/进程恢复执行回归。Windows/WSL 重启、休眠或真实网络变更须在明确维护窗口由用户执行后采证，不擅自中断业务。
5. [x] 文档：将第三批步骤补到现有用户验收与自启说明；草案、索引和类型化结果按本轮真实证据更新，区分产品功能、模拟、历史实测和新增实测。CHK-439 最低 Docker 版本仍独立保留。
6. [x] 本轮收尾：运行相关回归和全量门禁；仅停止自己创建的测试服务，核对既有服务与配置未变化；使用台账 CLI 同步任务、统计并 check；保持待提交。

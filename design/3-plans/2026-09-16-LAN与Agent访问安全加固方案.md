# LAN 与 Agent 访问安全加固方案（20260916）

> **归属复核（2026-10-15）**：部分落地，继续作为活动方案。HTTPS 首版与 `instanceBindHost` 能力已有 DEV-155 交付记录；H2 的整体端口收敛策略、H3 的远程 Agent 身份与安全门槛不能据此视为全部完成。下文为原始路线及决策背景，当前状态以台账为准。

> 依据：2026-09-16 局域网部署的黑盒安全评估与明文 HTTP 风险分析（CHK-343）。本文只保留类型化风险与加固设计；真实目标、扫描明细、测试账号与操作记录保留在本地检查点。
> 动因：后续计划对本机 / 局域网开放 Agent 访问能力（AGC M2 远程主体），传输与凭据安全问题必须先行收口。
> 关联：`design/2-achievement/对端网络安全测试总结-20260730.md`（上一轮对端测试）、`design/3-plans/2026-09-15-lwa-agent-collaboration-design.md`（Agent 协作设计）、task-list CHK-343 / OPS-180。

## 1. 目标与非目标

**目标**

1. 把 CHK-343 实测确认的问题逐项收口（信息泄露、暴力破解面、安全头、传输明文）。
2. 在开放 Agent 访问（尤其 M2 远程主体）之前，建立"传输加密 + 端口收敛 + 独立凭据 + 审计"四件套。
3. 保持 LWA"导入即用"的产品体验：加固项默认值不破坏现有本机工作流，LAN 暴露面按配置显式收紧。

**非目标**

- 不做多租户隔离、网络隔离、镜像签名（V1 既有边界，见 `docs/security-boundary.md`）。
- 不处理实例应用自身的业务漏洞（如 prd-review 的开放注册）——LWA 侧只提供模板默认值与文档引导。
- 不在本方案内实现 M2 Agent 身份体系（仅定义其前置条件）。

## 2. 威胁模型（类型化）

| 编号 | 威胁主体 | 能力假设 | 应检查的边界 |
| --- | --- | --- | --- |
| T1 | LAN 无凭据主体 | 只知道一个页面入口 | 管理 API 鉴权、文档端点、静态资源隔离及应用注册策略 |
| T2 | LAN 在径主体 | 可观察或修改传输 | HTTP 明文中的凭据与页面完整性；本轮未实际执行中间人干扰 |
| T3 | 凭据持有者 | 持有效管理凭据 | 凭据权限范围、审计及远程 Agent 的独立身份 |
| T4 | 实例应用漏洞 | 可直接访问业务端口 | 应用登录、开放文档、请求限制与绕过统一网关的访问面 |

部署可能同时存在网关、管理面、实例直连与运维入口；Caddy admin 应限回环。这里描述角色及安全约束，不公布某台机器的端口扫描结果，也不把历史观察当作当前配置。

## 4. 加固项

### H0 快速修复（应用/配置层）

#### H0-1 manager 关闭默认文档端点

- **历史设计输入**：FastAPI 默认 `/docs` `/redoc` `/openapi.json` 无鉴权 200（F1）。
- **方案**：`manager_api.py` 创建 FastAPI 实例时 `docs_url=None, redoc_url=None, openapi_url=None`；新增配置 `managerExposeApiDocs`（默认 `false`，仅 loopback 客户端 + 有效 token 时经显式开关开启，便于调试）。
- **验收**：LAN 无 token 访问三端点 404；loopback 开关开启后可访问且需 token。

#### H0-2 鉴权失败速率限制

- **历史设计输入**：manager token 校验与实例应用登录均无速率限制（F3），token 为 30 字符随机串本身不可穷举，但应用密码可在线爆破。
- **方案**：manager 侧在 `_verify_token` 外层加每源 IP 失败计数（如 5 次/分钟，窗口滑退）；应用侧属实例代码，LWA 在 Python 模板（`dockerfile_templates.py` / skills 文档）中给出限速中间件示例与默认开启建议。
- **验收**：连续失败后 429/延迟惩罚；成功 token 不受影响。

#### H0-3 网关安全头与 banner 收敛

- **历史设计输入**：`Server: uvicorn` 经反代透传，无基础安全头（F6）。
- **方案**：Caddy 别名站点片段与 builtin 网关统一注入 `X-Content-Type-Options: nosniff`、`X-Frame-Options: SAMEORIGIN`；CSP 因实例内容不可预知（内联脚本普遍），仅提供配置项 `gatewayCspHeader` 默认不设。`Server` 头经 Caddy `header -Server` 移除（builtin 网关同步处理）。
- **验收**：`:8080` 别名响应无 `Server` 泄露、带 nosniff/XFO；不影响既有页面渲染。

#### H0-4 实例模板与文档引导（应用层问题，LWA 侧引导）

- **方案**：Python/Node 应用模板默认关闭 openapi/docs（或挂鉴权）；`docs/agent-guide.md` 与导入 skill 增加"对外暴露的应用请自查开放注册/默认文档/限速"清单；`lwa doctor --profile full` 增加对运行中 python 实例的 `/openapi.json` 探测告警（warn 级，不阻断）。
- **验收**：新导入 FastAPI 类实例默认不暴露 openapi；doctor 能报出存量暴露实例。

#### H0-5 清理测试残留

- 按本地清单删除测试账号与临时源码；是否保留演示实例由用户决定。公开文档不记录实际账号、对象 ID 与机器路径。

### H1 传输加密（F4 根因，双路线）

> 结论先行：**HTTPS 只有同时满足"证书被真正校验 + 无明文降级入口 + 直连端口同步收敛"三条件，T2 改写/嗅探才真失效**（详见 CHK-343 会话分析）。IP 字面量访问无 HSTS（RFC 6797 仅对域名生效），故"只加 443 不关 8080"是不完整方案。

#### 路线 A：Overlay 网络收口（零代码，推荐起步）

- **方案**：LWA 各端口（8080/17800/18000+）仅监听 tailnet 地址或用主机防火墙限制来源为 tailnet 网段（100.64/10）；LAN 侧不再可达。tailnet 内流量 WireGuard 加密，T1/T2 均无从下手。
- **改动**：纯运维（`ufw`/`firewalld` 规则 + `local-web.yml` 绑定地址调整），LWA 零代码；`docs/` 增加操作手册章节。
- **代价**：访问需装 Tailscale 并入网；"给 LAN 里任意设备开个网页看看"的便利性下降。
- **验收**：从非 tailnet 的 LAN 机器全端口扫描仅剩 SSH（或全闭）；tailnet 内功能全量正常。

#### 路线 B：Caddy 内部 CA 的 HTTPS 产品化（LWA 新特性，立项实施）

1. **H1-B1 网关 TLS**：Caddyfile 生成支持 `tls internal`（Caddy 内嵌 CA 自动签发），配置项 `gatewayTls`（`off`/`internal`，默认 `off` 保持兼容）；启用后 `:8443`（或复用 8080 改义）服务 HTTPS。
2. **H1-B2 根证书分发**：新增 `lwa ca export`（导出根证书 + 各客户端安装说明）；`lwa manager on` 启动横幅提示未安装根证书的首次访问会告警——**禁止**"自签 + 用户点穿警告"的用法（等于把明文攻击升级为换证书 MITM）。
3. **H1-B3 明文入口收敛**：`gatewayTls=internal` 时 8080 明文默认关闭（配置 `gatewayPlainRedirect` 可选 308 → https，但须文档说明 IP 访问无 HSTS、重定向可被在径剥离，不是安全边界）。
4. **H1-B4 URL 体系适配**：`lanUrl`/`routeUrl`/`lwa access refresh`/管理页展示全部按 https 合成；`?token=` 便利通道在 https 下保留但文档优先级降级。
5. **H1-B5 manager 收敛进网关**：`:17800` 收敛为 loopback 监听，LAN 经 Caddy `https://<host>:8443/manager/` 反代（复用网关证书），彻底消灭明文 token 传输面。
- **验收**：未装根证书的客户端访问得到硬告警且文档指引安装；装后无告警；8080 明文关闭；wireshark 在径抓包无明文凭据；`lwa doctor` 新增 TLS 状态检查。

**历史决策说明**：路线 A 是当时讨论的外部组网选项，不能理解为 LWA 默认安装或修改网络。当前边界以 2026-10-19 的适配草案为准：尊重用户现有网络；路线 B 的产品实现状态仍按台账逐项核对。

### H2 端口收敛——网关单一入口（F5）

- **方案**：新增配置 `instanceBindHost`（默认 `0.0.0.0` 兼容现状；收紧场景设 `127.0.0.1`），静态实例与容器端口映射同步生效；`lwa doctor` 检查"实例直连端口对 LAN 开放"并提示。文档明确：收紧后 `lanUrl` 直连语义退化为 `localhostUrl` 兜底，路径别名成为唯一 LAN 入口——与 H1 配套后即"单入口 + 加密"。
- **兼容性**：无别名且未配 TLS 的实例在收紧后将无法 LAN 直连——doctor 与 `lwa access review` 需给出明确迁移提示（设别名或保持宽松绑定）。
- **验收**：`instanceBindHost=127.0.0.1` 时 LAN 扫描 18000+ 全闭，别名访问正常。

### H3 Agent 开放前置条件（M2 远程主体启动门槛）

> 现状：M1（本机回环 + 复用 manager token + Header 凭据 + scope + 源根校验，`agent/auth.py`）设计完备；M2 开放 LAN Agent 前，以下为**硬性前置**：

1. **H3-1 传输加密就绪**（依赖 H1）：Agent 凭据绝不裸奔明文——远程 Agent 通道仅在 `gatewayTls` 生效或 tailnet-only 暴露下开放，`agent-info.json` 的 `mcp.enabled` 与此联动。
2. **H3-2 独立 Agent 凭据**：M2 不复用 manager token（当前 token = 全权，T3 无制衡）；引入独立 Agent 身份（per-agent 凭据 + scope 子集，最小权限默认只读，`deploy:*` 显式授予），凭据可单独吊销、审计可归因。
3. **H3-3 审计与限速**：所有 Agent 写操作在 `manager.log` 落 `audit agent <principal> <action> <target>`（沿用 remove audit 先例）；Agent 通道按 principal 限速。
4. **H3-4 发现端点收敛开关**：`/llms.txt` `/agent-info.json` `/agent-guide` 增加配置 `agentDiscoveryExposure`（`lan`（默认，现状）/`local`/`off`），收紧部署可不自报家门；同时修正 `/agent-guide` 版本号滞后问题（对端报 V0.8.14，实为 V0.8.17）。
5. **H3-5 危险操作护栏复用**：M2 的 plan/apply 干跑模式与幂等键（AGC 设计已有）为强制路径，不允许绕过 apply 审批直接变更。

## 6. 验收总则

每项落地后复跑 CHK-343 的黑盒用例集（端口扫描、未授权探测、schema 抓取、限速、安全头、SSRF 编码绕过）作为回归；最终状态验收目标：

1. LAN 无凭据扫描者：仅见网关（或 tailnet-only 全隐），无任何 schema/版本泄露（除显式保留的发现端点）。
2. LAN 在径攻击者：无明文入口可剥离、无裸奔凭据可嗅探（wireshark 实证）。
3. Agent 开放时：独立凭据 + 最小 scope + 全量审计 + 干跑护栏，且 1/2 依然成立。

## 1. 数据层（schema v7）

- `registry/connection.py`：`CURRENT_SCHEMA_VERSION` 6 → 7；v7 迁移给 builds 表加 4 列：
  `image_ref TEXT`、`image_id TEXT`、`source_hash TEXT`、`config_snapshot TEXT`（可空，存量行不受影响）。
- `registry/dao.py`：新增 `record_build_artifacts(build_id, *, image_ref, image_id, source_hash, config_snapshot)`；
  `list_builds` 本身 `SELECT *`，自动带出新列。

## 2. 全局配置

- `config.py`：`imageRetention: int = 3`（ge=1, le=50）；`selfHealPreferLastGood: bool = True`；
  `CONFIG_EXAMPLE` 补两段中文注释。均为新增键，旧配置文件零影响。

## 3. 新模块 versions.py（留档与 GC）

- `build_snapshot_dir(workspace, iid, build_id)` → `apps/<id>/docker/builds/<build_id>/`。
- `snapshot_config(...)` / `restore_config_snapshot(...)`：复制/恢复 GENERATED_FILES（复用 rebuild_txn 的文件清单）。
- `tag_build_image(image_id, ref)` / `resolve_repo_image_id(repo)`（`docker image inspect <repo>:latest`）。
- `image_exists(ref)` / `image_disk_usage_bytes(refs)`。
- `gc_build_artifacts(workspace, config, registry, iid, *, in_use_image_id)`：
  保留最新 `imageRetention` 个有镜像引用的构建；**永远不删**正在使用的镜像与最近一个可用版本
  （二者计入保留数）；被 GC 的构建 `docker image rm <image_ref>`（忽略不存在）并删除快照目录。
  GC 失败只告警不阻断部署。
- `list_versions(registry, iid)`：builds 行 + 镜像存在性 + 磁盘占用汇总。

## 4. 新模块 rollback.py（回滚编排）

- `RollbackNeedsYes`：preStart/buildHooks 含迁移命令（alembic/migrate/prisma）且未 `--yes` 时抛出。
- `select_rollback_target(registry, iid, *, exclude_build_id)`：最近一个 status=success、镜像仍在、
  快照目录在的构建。
- `rollback_instance(workspace, config, registry, iid, *, to_build_id=None, yes=False,
  expected_revision=None, source="cli", run_alias_guard=True)`：
  1. instance_lock + `_ensure_revision_locked`（S2-09）；
  2. 选目标（默认上一个可用版本），校验镜像与快照存在；
  3. D8 校验：preStart 含迁移命令须 `yes=True`，否则抛 `RollbackNeedsYes`；
  4. 内存暂存当前生成物 + 当前 imageId；`stop_or_abort`；
  5. 恢复快照生成物，`docker tag <image_ref> <repo>:latest`，`runtime.up`；
  6. `_evaluate_container_verification` 验证；**失败时补偿**：down → 恢复暂存生成物 →
     原镜像打回 latest → up 原版本 → 抛 HostingError（lastOperation=failed）；
  7. 成功：manifest 更新 imageId/hostPort、status=RUNNING、lastOperation(kind=rollback, succeeded)、
     upsert + revision CAS +1（observed_revision 模式，同 rebuild_instance）、事件 `rollback`；
  8. `run_alias_guard` 时跑 `maybe_verify_alias_after_start`。
- `restore_last_good(...)`：daemon 自愈入口，`yes=True`、跳过别名守卫、排除当前失败构建。

## 5. hosting.py 集成（host_container 成功路径）

- build 成功后（`compose_build_done` 处）：解析 `repo:latest` 新 imageId → 打 `repo:b<build_id>`
  → 快照生成物到 builds 目录 → `record_build_artifacts`（image_ref/image_id/source_hash/config_snapshot）。
- 部署成功收尾（verification 通过后）：`gc_build_artifacts`（in_use = 新 imageId），失败仅告警。
- 补偿路径不动：b<id> 标签与快照保留给后续 GC 判定。

## 6. daemon 自愈（selfHealPreferLastGood）

- `reconcile` 拉起前：容器实例 && 配置开启 && `lastOperation.status=failed` &&
  存在可回滚目标时，先走 `restore_last_good`；失败回退原有 `start_instance`。

## 7. CLI

- 新模块 `cli/versions.py`：`lwa versions <id>`（构建号/时间/源码哈希/镜像是否仍在/构建结果/占用）；
  `lwa rollback <id> [--to N] [--yes]`（D8 提示、preStart 迁移醒目告警、别名守卫收口摘要、退出码 4）。
- `cli/status.py`：`lwa status <id>` 容器实例追加「保留版本：N 个 · 占用 X」。

## 8. 管理页 API + 前端

- `POST /api/instances/{id}/rollback`：body `{toBuildId?, expectedRevision?, confirm?}`；
  走 `_lifecycle_op` 同款 revision 预检；调用 `rollback_instance(yes=confirm)`。
- 实例详情响应加 `versions` 字段；前端详情抽屉渲染「版本」分区（构建号/时间/哈希/镜像在否/结果），

  只回滚镜像与生成配置，不回滚 data/；preStart 含迁移时红色警示数据库结构可能不兼容）。

## 复核修复（2026-10-14，独立复核后）

1. **默认回滚选中了当前在用版本**（严重）：`select_rollback_target` 新增 `exclude_image_id`；手动回滚（未传 `--to`）时排除当前在用镜像（registry 容器行 image_id，回退 manifest imageId；比较时统一去掉 `sha256:` 前缀）。daemon 自愈路径保持原语义（排除失败构建本身，不排除 manifest 中可能仍指向旧版的 imageId）。回归：`tests/scripts/test_s3_review_fixes.py` 4 例。
2. **镜像占用统计整组归零**（高危）：`docker image inspect` 任一引用不存在即非零退出，但 stdout 仍含其余镜像 JSON。`image_disk_usage_bytes` 改为不看返回码、直接解析 stdout；无法解析才回 0。已用本机 docker 实测该行为。回归 2 例。
3. **`lwa logs --timeline` 遇损坏 manifest 直接崩溃**：manifest 读取包一层容错，提示“manifest 读取失败，时间线不含最近操作”，事件与构建记录照常输出。回归 1 例。
4. **生成物手改漏报**：“生成物比 manifest 新”改为取 compose / Dockerfile / .env 三者中最新 mtime 比较（此前只比 compose）。回归 1 例（只改 .env 时必须报出）。

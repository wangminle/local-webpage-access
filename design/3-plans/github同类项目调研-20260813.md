# GitHub 同类项目调研（2026-08-13）

> 调研目标：梳理 LWA 项目特色，检查 GitHub 上是否存在同构或近似项目。
> 结论一句话：**在本次列出的候选项目及已核对公开资料中，没有发现与 LWA 完全同构的项目。** zip/文件夹导入、inbox 自动导入、五层识别流水线主体、端口池/LAN 治理、路径别名门禁等能力在各分类里只出现一部分；这不是穷尽检索，不能证明全球不存在同构实现。
>
> 星标、仓库状态均为 **2026-08-13 GitHub API 快照**。功能描述以官方文档/README 为主，未逐项读竞品源码。复核见 [[CHK-203]] [[CHK-204]] [[CHK-205]]。

### 1.2 项目特色摘要

| 维度 | 特色 |
|---|---|
| 导入 | `lwa import xxx.zip` / `--from-dir`；`inbox/` 由 daemon 自动导入；zip-slip/符号链接/炸弹防护；sha256/内容指纹校验；`--update` 原地升级保留 id/端口/data/别名（事务期用 `current.old`，成功后删除；另留一份 `original.zip.bak`，**没有**多版本索引） |
| 识别 | 五层流水线主体已实现（证据收集→候选生成→静态预检→实证校验→收敛诊断）。Gate 与层的映射是：**Gate-A=Layer 2 静态预检，Gate-B=Layer 0+1 证据/多候选识别，Gate-C=Layer 3+4 实证校验与收敛诊断**。Gate-A 原战术范围已落地，修订后的 SQLite 安全自动修正 **A.R01 尚未收口**；Gate-C 代码与模拟回归通过，真实 Docker 门控 **[[TST-005]] 进行中**。Scanner 设计文档明确：不得把「模型和模拟测试存在」写成「全部退出标准已满足」。含 shell 操作符防护、SQLite 绝对路径、Alembic cwd、Node 子目录候选、sourceSubdir 扁平复制 |
| 托管 | 静态→共享 Caddy 网关（builtin `http.server` 兜底）；SPA→自动 npm build；全栈→自动生成 Dockerfile + Docker Compose |
| 网络 | 端口池隔离（registry 登记 + 宿主机实际监听双重查重）；lanUrl 读时合成 + DHCP 漂移节流自愈；路径别名（SPA 绝对路径/API 路径错位自动检测）；网关原子切换（caddy↔builtin 预检/回滚/degraded） |
| 治理 | SQLite Registry（**7 张业务表** instances/containers/static_sites/ports/events/builds/resources **+ 1 张** `schema_version`；WAL、外键级联）。构建历史/最终状态写主 Registry 的 `builds` 表；跨进程限流和活动任务协调另用与主库同目录的 `registry/build-locks.db`（`build_slots` + `build_tasks`，含 owner/worker/cancel 状态）；浏览量另用 `run/pageviews.db`。后两个独立库均不计入 Registry 的 8 张表 |
| 管理页 | FastAPI + Vue 单页前端；token 鉴权（168h 自动轮换、loopback 免 token）；LAN stale 横幅；能力降级横幅；双阶段安全删除 |
| 运维 | `lwa doctor`（平台矩阵、CapabilityReport、fail-closed 不假绿）；宿主机装配（国内源 Docker/Caddy 安装脚本）；autostart（systemd/launchd + 深检/repair）；workspace relocate（同卷原子迁移 verify/rollback）；`lwa update` 热重载编排 |
| 安全 | 导入期审计（zip 成员、**平台生成的** Compose/Dockerfile 写前拦截 `ADD <url>`、`curl\|sh` critical）；LAN 绑定 + token 校验。该描述不代表任意自带 Dockerfile、构建脚本或源码已被完整审计/沙箱化 |
| 平台 | 仅 Ubuntu LTS / Debian Stable / WSL2 / macOS；Windows 原生 hard fail |
| AI 协作 | 19 个 SKILL.md 覆盖环境初始化、导入、托管、容器、生命周期、自启动、迁移、访问复核、排障 |

## 四、结论

1. **在本次列出的候选中，没有发现完全同构项目。** 最接近的组合仍是：理念像 Piku，交付方式像 CapRover/Dokku 的压缩包路径，品类像 Coolify/Dokploy/Easypanel，受众像 CasaOS/1Panel。这是样本结论，不是穷尽证明。
2. LWA 有辨识度的组合是 **导入即用**（zip/文件夹 + **inbox 守护进程** + 免手写配置识别）和 **LAN 原生治理**（端口池 / 地址漂移 / 别名门禁）。「能吃 zip」本身并不稀缺（CapRover、Dokku `git:from-archive`、Rainbond 源码包都能）；稀缺的是 inbox 自动导入并走识别流水线。
3. 「护城河」「没有人打得动」属于**产品判断**，不是调研事实。发现层建议仍成立：补 Topics、启用 Releases。
4. 功能级对比（含矩阵勘误、优先级四维评分）见 [自托管PaaS对比分析-20260813.md](./自托管PaaS对比分析-20260813.md)。

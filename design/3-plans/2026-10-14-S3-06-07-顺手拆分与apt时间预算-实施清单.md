## S3-07 apt 总体时间预算（DEV-146 / issue #36）

1. [x] `BuildMirrors.aptBudget`（秒，`0..3600`，默认 `0` = 不限，渲染结果与旧版逐字一致）。
2. [x] `dockerfile_templates._apt_body`：设预算后每个源候选把 `apt-get update` +
   `install --download-only` 整体放进 `timeout -k 10 <budget> sh -c '…'`，到点连同子进程终止并由
   `||` 切下一个源；真正的 dpkg 安装在下载完成后离线执行、不受预算约束，因此不会留下半安装状态。
   系统依赖层与 Node 工具链层共用。
3. [x] 仅 `timeout` 退出码 124/137 才输出“总时间预算”提示；源 503、解析失败等普通失败码原样透传，
   不误报预算超时（真实构建中发现并修正）。
4. [x] 失败提示与 `build_diagnostics` 的 apt 建议文案补充 `aptBudget`。
5. [x] 测试：渲染（默认不变 / 逐源包裹 / Node 层 / 取值边界 / `resolved()` 保留）；假 `apt-get` 在真实 `sh`
   中验证挂住被杀、普通失败不误报、成功路径“下载 + 离线安装”共 3 次调用；真实 Docker 用例
   `test_docker_apt_budget_integration.py`（静默源容器，两个源各被 4s 预算终止，约 9s 失败，对照未设预算
   60s 仍挂住）。
6. [x] 文档：FAQ、运维手册、已知限制（预算过小会误判慢但正常的下载；需 coreutils `timeout`）、
   README 与 `local-web.yml` 模板注释。

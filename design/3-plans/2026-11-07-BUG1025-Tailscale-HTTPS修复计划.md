# BUG-1025：Tailscale HTTPS 修复计划

目标：恢复本机已公布的 Tailscale HTTPS 别名入口，保持 LAN 与回环访问，以及现有 CA 和管理鉴权。

方案：复用已有只读 Tailscale 探测，将在线本机 IPv4/IPv6 纳入 Caddy TLS 主机集合；在现有地址同步中比较完整主机集合，覆盖 Tailscale 新增、变化和断开，以及 WSL 额外入口，两个 HTTPS 端口分别判断。WSL 仍沿用现有多 SAN 证书策略，双栈主机在显式 bind 时覆盖 IPv6。

其他方案：只改运行时 Caddyfile 会被后续重载覆盖；把 manualLanIp 改为 Tailscale IP 会改变 LAN 地址语义；均不采用。用户已在故障定位后授权立即修复更新。

待办：
1. 新增缺陷回归，验证修复前失败：TLS 主机/IPv6/离线、双端口同步/幂等/关闭保护、WSL 地址共存。
2. 修复主机生成与刷新比较，保留现有未提交工作；运行专项、Caddy 语义校验和项目门禁。
3. 审查本次差异，更新 HTTPS 用户说明；热重载本网关，协调重启需要载入代码的 LWA 后台服务，验证原 URL、资源、证书校验及管理鉴权。
4. 更新 BUG-1025 及检查台账。服务端访问自身地址不替代用户手机或另一 tailnet 节点验收；CHK-520 保持待办。

不提交或发布远端仓库；不修改 Tailscale/ACL/防火墙；不重建业务实例。

审查补强：LAN 探测失败沿用原有跳过写盘/同步保护；Tailscale 探测采用30秒锁内单飞缓存，未知保留最近可信地址及既有配置名称，不阻断LAN变化恢复，明确断开才删除对应额外名称。manual LAN维持显式刷新语义。新增对应回归并复审，未扩大到独立后台调度。

执行结果：四步均已完成；完整门禁4866/23，另启用2项真实Caddy TLS集成通过；本机已更新并严格验证原IPv4 HTTPS。详见 design/5-checkpoints/2026-11-07-BUG1025-Tailscale-HTTPS修复与本机更新验收.md。手机/其他节点及本机Tailscale IPv6传输仍未验收通过。

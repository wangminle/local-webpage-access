## 4. IMP-050 — 生产 CLI 与工作区解耦安装

> **状态**：需求触发后重新论证（PLN-033；原合集 Task 11/P2）。多工作区或正式部署形成持续需求后再立项。

### 4.1 需求

安装和升级 `lwa` CLI 的 Python/venv/入口脚本与具体工作区目录解耦，避免 editable 安装或解释器路径钉死旧工作区，导致 relocate 后 CLI、自启和 update 难以恢复。

### 4.2 关键决策（待拍板）

| 编号 | 决策点 | 倾向 |
| --- | --- | --- |
| **050.a** | 推荐布局 | 用户级或全局 venv + `lwa --workspace`/环境变量指向工作区 |
| **050.b** | 与 autostart | 单元固定 CLI 解释器，工作区仅作为显式参数或环境变量 |
| **050.c** | 与开发模式 | 开发机保留 editable；生产安装、升级与回滚采用稳定通道 |
| **050.d** | 多工作区 | 明确默认工作区选择、并发操作和状态隔离，不自动合并实例列表 |

### 4.3 现状触点

- 当前 clone + editable 安装与工作区目录耦合，简单单工作区场景成本最低。
- autostart 单元和 update continuation 都依赖稳定解释器及明确工作区。
- `workspace relocate` 可修复工作区数据，但不等价于迁移 CLI 安装本身。

### 4.4 WBS（立项门槛后执行）

| ID | 工作包 | 完成标准 |
| --- | --- | --- |
| **050.01** | 使用场景与安装模型 | 单/多工作区、开发/生产、升级/回滚矩阵拍板 |
| **050.02** | CLI 工作区解析 | 参数、环境变量、默认值优先级无歧义且 fail-closed |
| **050.03** | 安装/升级工具链 | venv、入口脚本、版本切换和恢复路径可重复执行 |
| **050.04** | autostart/update 适配 | 单元与 continuation 使用稳定解释器，不钉死旧工作区 |
| **050.05** | relocate 与多工作区回归 | 移动工作区无需重装 CLI；不同工作区状态不串扰 |

### 4.5 验收标准

- 按生产文档安装后，移动同卷工作区无需重装 CLI。

## 6. IMP-066 — Flask/Django 后端使用生产服务器模板

## 8. IMP-068 — Ubuntu 22.04 的 Python 3.13 可执行安装路径

### 9.3 探测频率评估与推荐

| 方案 | 收益 | 代价与结论 |
| --- | --- | --- |
| **启动立即探测 + 每 30 秒后台刷新（推荐）** | 不依赖浏览器是否打开；运行中开关 Tailscale 可自动发现；所有页面共享缓存 | 每个管理服务进程每分钟约 2 次本地轻量探测，时间间隔可预测；前端沿用现有 15 秒轮询读取缓存 |
| 每 5 秒后台刷新 | 状态变化更快可见 | 每分钟约 12 次探测，对家庭服务器此入口的收益有限 |
| 订阅本地状态事件 | 状态变化能更快推送，减少定时进程 | 引入常驻订阅、断线重连及平台差异处理；当前范围暂不采用 |

推荐实现约束：

1. 单次以 `tailscale status --json` 读取本机状态与自身 IP，超时上限 **2 秒**；校验 JSON、运行状态、自身地址及可用性，不能仅凭可执行文件存在或残留 IP 判断已组网。失败和未知状态不可继续提供旧的可切换结果。具体兼容字段按支持的客户端版本用样例测试固定。
2. 首次探测结束后按 **30 秒**间隔继续探测，未安装/已关闭也继续检查，从而自动发现后续安装或启用。探测不重叠、不在请求或逐实例循环中执行；服务关闭时停止并回收后台任务。
3. 快照建议字段：`available`、`state`、`ipv4`、`ipv6`、`selectedIp`、`checkedAt`、`reason`；放在进程内缓存，鉴权 API 只返回本机必要字段，不返回 peer/用户/完整原始状态。
4. 建议新增 `GET /api/network-context` 只读缓存，接入页面首载及现有 **15 秒**刷新周期；缓存未就绪直接返回 unknown，不在 GET 内补跑探测。多标签页不能增加系统探测次数。
5. 正常前台页面、API 成功返回时，按“轮次完成后等待 30 秒 + 单轮最多 2 秒 + 前端最多 15 秒”，状态变化约 **47 秒内**反映；这不是后台休眠标签页或网络中断时的时限保证。
6. 缓存超过 **60 秒**未成功更新即视为过期、不可切换；前端 API 失败同样不能无限保留旧 available，按快照时效自动回退。页面从后台恢复时立即读取缓存。

参考：[Tailscale 官方 CLI 文档](https://tailscale.com/docs/reference/tailscale-cli)说明 `status --json` 提供机器可读状态；自身 IP 与状态字段定义见 [官方 ipnstate 源码](https://github.com/tailscale/tailscale/blob/main/ipn/ipnstate/ipnstate.go)。30 秒周期、2 秒超时及回退方式是本项目的设计建议，并非官方推荐参数。

## 修改 1：CHK-V03 SQLite 文件名硬编码（数据丢失风险）

**文档约束**（§6.4 CHK-V03 + §10.2 评审后限制）：
> 自动修正前提：已确认应用读取 DATABASE_URL，已解析原数据库文件名，目标位于持久卷，且不会切换到新空库

**当前问题**：
- `compose.py:38` 硬编码 `_SQLITE_DB_URL = "sqlite:////app/data/app.sqlite"`
- `compose.py:193` 对所有 SQLite 项目无条件注入 `DATABASE_URL=sqlite:////app/data/app.sqlite`
- 若项目原库叫 `bookshelf.db` / `app.db` / `foo.sqlite3`，注入后应用指向全新空库 → **数据丢失**
- `DatabaseConfig`（models.py:83）没有承载原文件名字段

**修改方案**：
1. `models.py` `DatabaseConfig` 新增可选字段 `dbFilename: str | None = None`（利用已有 `extra="allow"`，但显式声明便于消费）
2. `scanner.py:576` `_detect_sqlite`：把 `summary.sqlite_files[0]` 的文件名存入 `DatabaseConfig.dbFilename`（若存在）
3. `compose.py:38` 删除硬编码常量；`generate_env` 改为：若 `manifest.database.dbFilename` 存在则用原文件名，否则保留 `app.sqlite` 作为兜底
4. `preflight.py:186` `_check_db_path` 的 action 文案改为体现实际文件名，而非硬编码 `app.sqlite`

**影响的测试**：
- `tests/test_compose.py:171` 断言 `"DATABASE_URL=sqlite:////app/data/app.sqlite"`：manifest 无 dbFilename 时仍走默认，**测试不用改**
- `tests/test_compose.py:189`：同上，RUNTIME_ROOT 布局
- 新增测试：manifest.database.dbFilename="bookshelf.db" 时，env 含 `sqlite:////app/data/bookshelf.db`

## 修改 2：CHK-V02 漏检裸 `()` 操作符

**文档约束**（§6.4 CHK-V02）：
> 检查逻辑：`re.search(r'[&\|\;<>$`(\)]', entry.start)` 或 `'$(' in entry.start`

**当前问题**：
- `dockerfile_templates.py:641` 正则 `_SHELL_OPERATOR_RE = re.compile(r"&&|\|\||;|\$\(|`")` 只匹配 `$(`，不匹配裸 `(` `)`

**修改方案**：
- `dockerfile_templates.py:641` 正则扩展为 `r"&&|\|\||;|\$\(|`|\(|\)"`，增加对裸 `(` 和 `)` 的匹配
- 注意：需确认现有简单命令不含裸括号（如 `uvicorn app.main:app`），避免误报。经检查，scanner 生成的命令都不含裸括号

**影响的测试**：
- 新增 `tests/test_preflight.py`：含 `()` 的命令触发包裹
- 确认现有简单命令不误报

## 修改 3：CHK-V04 解析 alembic.ini 的 script_location

**文档约束**（§6.4 CHK-V04）：
> 检查逻辑：若 `evidence.alembic_config` 不为 None：检查 `script_location` 是否相对路径；若是，验证 `<alembic.ini 所在目录>/<script_location>` 是否存在

**当前问题**：
- `preflight.py` 导入了 `configparser`（:22）但从未使用
- `_check_alembic_cwd` 靠"alembic.ini 在不在子目录"近似判断，不解析 `script_location`
- 漏判场景：alembic.ini 在顶层但 `script_location=migrations/`（相对路径）不会被检测

**修改方案**：
- `_check_alembic_cwd`（preflight.py:215）增加 `configparser` 解析：读取 alembic.ini 的 `[alembic] script_location`
- 若 `script_location` 是相对路径（不以 `/` 开头），验证 `<alembic.ini 所在目录>/<script_location>` 是否存在
- 若 alembic.ini 在子目录 **或** script_location 是相对路径且目录不存在 → 标记风险并维持现有 cwd 编排逻辑
- 现有的"子目录 + start 含 alembic → 注入 cd 序列"逻辑保留不变（这是 Gate-A 的有界修正，文档允许）

**影响的测试**：
- 现有 `test_chk_v04_alembic_at_root`：script_location=alembic 在顶层且目录存在 → 通过（行为不变）
- 新增测试：顶层 alembic.ini + script_location 指向不存在目录 → 标记风险
- 现有子目录测试保持通过
